# การตั้งค่าคิวและประวัติการอ่าน — VoxWeaveTTS (Source หลัง v0.9.5)

ฟีเจอร์นี้อยู่ในโค้ดพัฒนาล่าสุด **ยังไม่รวมใน GitHub Release v0.9.5** และทำงานเป็นอิสระในโหมด YouTube LIVE API, YouTube Browser, Discord Bot, Discord Client, TikTok TikFinity และ TikTok Browser/Extension

## ความยาวข้อความสูงสุด

- ช่วงการตั้งค่า **20–8,000 ตัวอักษร** ต่อข้อความจากแหล่ง LIVE (ค่าเริ่มต้นยังเป็น **240**)
- ข้อความยาวเกินค่าที่กำหนดจะถูก **กรอง ไม่ได้ถูกตัดให้สั้นลงเพื่ออ่าน**
- การรับข้อความยังขึ้นกับขีดจำกัดของแพลตฟอร์ม/API. ความยาว 8,000 ไม่ได้ทำให้ YouTube/TikTok ส่งข้อความได้ยาวเกินที่แพลตฟอร์มรองรับเอง
- ข้อความยาวมากอาจใช้เวลาแปล/สร้างเสียงนาน และขึ้นอยู่กับโมเดล/ทรัพยากร Windows
- หากเปิดอ่านชื่อผู้ส่ง ระบบจะส่งชื่อเป็นข้อมูลประกอบแยกจากเนื้อความจริง เพื่อรักษาลำดับการกรอง/แปลและลดปัญหาเพดานความยาวของเนื้อความ

## วิธีบันทึก

1. เปิดโหมดที่ต้องการแล้วตั้งค่า **คำที่ไม่อ่าน, ความยาวข้อความสูงสุด, อ่านอัตโนมัติ, สุ่มลดคิว, เกณฑ์เริ่มสุ่ม, จำนวนคิวที่เหลือ, ประวัติที่อ่านแล้ว (0–100)**
2. กด **บันทึกการตั้งค่าคิว/ความยาวข้อความ** ภายในโหมดนั้น และตรวจข้อความยืนยัน
3. โปรแกรมบันทึกค่าแยกโหมดใน `data/settings/source-queues.json` โดยใช้พาธสัมพัทธ์ในโฟลเดอร์โปรแกรม. การบันทึกแบบ Atomic และ Revision ช่วยป้องกันข้อมูลสูญหายหรือการเขียนทับจากหลายแท็บ
4. รีโหลดหน้าโปรแกรมแล้วจะโหลดค่าที่บันทึกไว้กลับมาโดยไม่ต้อง Import Profile. **คำกรองและความยาวข้อความจะมีผลต่อการเชื่อมต่อ Source ครั้งใหม่**; การแก้เกณฑ์สุ่มคิวในหน้าเว็บยังมีผลกับคิวปัจจุบันตามพฤติกรรมเดิม
5. ไม่บันทึก API Key, Discord Token, OAuth Secret หรือ Channel Credentials ในไฟล์ตั้งค่าคิวนี้. ระบบ Export/Import Profile เดิมยังใช้งานเหมือนเดิม

## ช่องติดตามข้อความแยกจากแชทเดิม

- **ข้อความที่กำลังแปลงเป็นเสียง / สถานะและข้อผิดพลาด:** แสดงข้อความที่ส่งไปสร้างเสียงจริง (รวมรูปแบบชื่อผู้ส่งถ้าเลือกเปิด) พร้อมสถานะ Preparing, Ready, Reading, Skipped หรือ Failed. ถ้าเกิดข้อผิดพลาดจะคงข้อความที่เกิดปัญหาไว้ให้ตรวจ
- **ข้อความที่อ่านแล้ว:** เพิ่มรายการเมื่อเสียง **เล่นจบจริง** (audio `ended`) เท่านั้น; งานที่สร้าง WAV เสร็จแต่ยังไม่เล่น, งานล้มเหลวหรือข้อความที่ถูกสุ่มลบ ไม่ถูกนับเป็นอ่านแล้ว
- จำนวนรายการย้อนหลังจำกัดโดย **ประวัติที่อ่านแล้ว (0–100)**. ตั้ง 0 จะไม่เก็บข้อความที่อ่านแล้วในช่องใหม่
- ช่องรายการแชทเดิมไม่ถูกแทนที่/เปลี่ยนความหมาย; คิว FIFO และการสุ่มลบเฉพาะข้อความรออ่านยังคงทำงานเหมือนเดิม
- ข้อความในแชทและข้อผิดพลาดแสดงด้วย Text-only DOM (ไม่รัน HTML/JavaScript จากผู้ส่ง)

## ความเป็นส่วนตัวและการตรวจสอบ

ข้อความที่กำลังสร้างเสียงและประวัติการอ่านอยู่ในหน้าเว็บขณะทำงาน ไม่เขียนข้อความแชทลงไฟล์ตั้งค่าคิว. หากต้องการดูว่าประโยคใดทำให้โมเดลสร้างเสียงล้มเหลว ให้ดูช่องข้อความปัจจุบันพร้อมสถานะข้อผิดพลาด ก่อนทดลองเปลี่ยนโมเดล เสียง หรือกฎการอ่าน

งาน Universal `.vwmodel v2` สำหรับระบบ Runtime/Environment ทุกรูปแบบเป็นแผนพัฒนาถัดไป **ยังไม่ถือว่าเสร็จในชุดแก้ไขนี้**
