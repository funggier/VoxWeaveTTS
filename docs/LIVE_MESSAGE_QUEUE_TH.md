# การตั้งค่าคิวและประวัติการอ่าน — VoxWeaveTTS (Source หลัง v0.9.5)

ฟีเจอร์นี้อยู่ในโค้ดพัฒนาล่าสุด **ยังไม่รวมใน GitHub Release v0.9.5** และทำงานเป็นอิสระในโหมด YouTube LIVE API, YouTube Browser, Discord Bot, Discord Client, TikTok TikFinity และ TikTok Browser/Extension

## ความยาวข้อความสูงสุด

- ช่วงการตั้งค่า **20–8,000 ตัวอักษร** ต่อข้อความจากแหล่ง LIVE (ค่าเริ่มต้นยังเป็น **240**)
- ข้อความยาวเกินค่าที่กำหนดจะถูก **กรอง ไม่ได้ถูกตัดให้สั้นลงเพื่ออ่าน**
- การรับข้อความยังขึ้นกับขีดจำกัดของแพลตฟอร์ม/API. ความยาว 8,000 ไม่ได้ทำให้ YouTube/TikTok ส่งข้อความได้ยาวเกินที่แพลตฟอร์มรองรับเอง
- ข้อความยาวมากอาจใช้เวลาแปล/สร้างเสียงนาน และขึ้นอยู่กับโมเดล/ทรัพยากร Windows
- หากเปิดอ่านชื่อผู้ส่ง ระบบจะส่งชื่อเป็นข้อมูลประกอบแยกจากเนื้อความจริง เพื่อรักษาลำดับการกรอง/แปลและลดปัญหาเพดานความยาวของเนื้อความ

## วิธีบันทึก

1. เปิดโหมดที่ต้องการแล้วตั้งค่า **คำที่ไม่อ่าน, ความยาวข้อความสูงสุด, อ่านอัตโนมัติ, สุ่มลดคิว, เกณฑ์เริ่มสุ่ม, จำนวนคิวที่เหลือ, ประวัติที่อ่านแล้ว (0–100)**
2. กด **บันทึกการตั้งค่าคิว/ความยาวข้อความ** ภายในโหมดนั้น และตรวจข้อความยืนยัน
3. โปรแกรมบันทึกค่าแยกโหมดใน `data/settings/source-queues.json` โดยใช้พาธสัมพัทธ์ในโฟลเดอร์โปรแกรม. การบันทึกแบบ Atomic และ Revision ช่วยป้องกันข้อมูลสูญหายหรือการเขียนทับจากหลายแท็บ
4. รีโหลดหน้าโปรแกรมแล้วจะโหลดค่าที่บันทึกไว้กลับมาโดยไม่ต้อง Import Profile. **คำกรองและความยาวข้อความจะมีผลต่อการเชื่อมต่อ Source ครั้งใหม่**; การแก้เกณฑ์สุ่มคิวในหน้าเว็บยังมีผลกับคิวปัจจุบันตามพฤติกรรมเดิม
5. ไม่บันทึก API Key, Discord Token, OAuth Secret หรือ Channel Credentials ในไฟล์ตั้งค่าคิวนี้. ระบบ Export/Import Profile เดิมยังใช้งานเหมือนเดิม

## ช่องติดตามข้อความแยกจากแชทเดิม

- **ข้อความที่กำลังแปลงเป็นเสียง / สถานะและข้อผิดพลาด:** แสดงข้อความที่ส่งไปสร้างเสียงจริง (รวมรูปแบบชื่อผู้ส่งถ้าเลือกเปิด) พร้อมสถานะ Preparing, Ready, Reading, Skipped หรือ Failed. ถ้าเกิดข้อผิดพลาดจะคงข้อความที่เกิดปัญหาไว้ให้ตรวจ
- **ข้อความที่อ่านแล้ว:** เพิ่มรายการเมื่อเสียง **เล่นจบจริง** (audio `ended`) เท่านั้น; งานที่สร้าง WAV เสร็จแต่ยังไม่เล่น, งานล้มเหลวหรือข้อความที่ถูกสุ่มลบ ไม่ถูกนับเป็นอ่านแล้ว
- จำนวนรายการย้อนหลังจำกัดโดย **ประวัติที่อ่านแล้ว (0–100)**. ตั้ง 0 จะไม่เก็บข้อความที่อ่านแล้วในช่องใหม่
- ช่องรายการแชทเดิมไม่ถูกแทนที่/เปลี่ยนความหมาย; คิว FIFO และการสุ่มลบเฉพาะข้อความรออ่านยังคงทำงานเหมือนเดิม
- ข้อความในแชทและข้อผิดพลาดแสดงด้วย Text-only DOM (ไม่รัน HTML/JavaScript จากผู้ส่ง)

## ความเป็นส่วนตัวและการตรวจสอบ

ข้อความที่กำลังสร้างเสียงและประวัติการอ่านอยู่ในหน้าเว็บขณะทำงาน ไม่เขียนข้อความแชทลงไฟล์ตั้งค่าคิว. หากต้องการดูว่าประโยคใดทำให้โมเดลสร้างเสียงล้มเหลว ให้ดูช่องข้อความปัจจุบันพร้อมสถานะข้อผิดพลาด ก่อนทดลองเปลี่ยนโมเดล เสียง หรือกฎการอ่าน

งาน Universal `.vwmodel v2` สำหรับระบบ Runtime/Environment ทุกรูปแบบเป็นแผนพัฒนาถัดไป **ยังไม่ถือว่าเสร็จในชุดแก้ไขนี้**

## ประวัติข้อความหลังแปลที่ส่งเข้าโมเดล TTS จริง

ในโหมดที่รับข้อความจาก Live/Discord/TikTok จะมีอีกช่องแยกต่างหากชื่อ **ข้อความที่ส่งเข้าโมเดลเสียงจริง หลังแปลและกฎการอ่าน (ประวัติที่อ่านแล้ว)** เพิ่มจากรายการแชทเดิมและประวัติที่อ่านแล้วก่อนหน้านี้ โดยมีเงื่อนไขดังนี้

- เนื้อหามาจาก **Speech Plan หลังแปลภาษา, กฎหลังแปล และพจนานุกรมการออกเสียง** ไม่ใช่ข้อความต้นทางหรือแค่ข้อความที่ประกอบก่อนส่งเข้า AI
- หากหนึ่งข้อความถูกอ่านหลายภาษา จะเห็นแต่ละช่วงข้อความที่ส่งให้โมเดล พร้อมรหัสภาษา Engine และ Voice ID โดยเก็บ **หนึ่งรายการประวัติต่อหนึ่งข้อความที่อ่านจนจบ**
- ถ้าข้อความถูกแบ่งย่อยเป็นหลาย Chunk สำหรับ TTS จะแสดง Chunk เหล่านั้นตามลำดับเช่นเดียวกับที่เรียกโมเดล และไม่เพิ่มจำนวนรายการประวัติสำหรับแต่ละ Chunk
- ใช้ค่าจำกัดเดียวกับ **ประวัติที่อ่านแล้ว (0–100)** หากตั้งค่าเป็น 0 ช่องใหม่นี้ก็จะไม่เก็บประวัติ
- ไม่บันทึกข้อความย้อนหลังลงในไฟล์ตั้งค่า และไม่ใช้ข้อความต้นทางแทนเมื่อข้อมูลหลังแปลไม่พร้อม
- เซิร์ฟเวอร์แยกข้อมูลที่ส่งเข้าโมเดลออกจาก API สถานะงานทั่วไป, Events และ Subtitle เพื่อไม่เผยแพร่เนื้อหาส่วนนี้โดยไม่จำเป็น หน้าจอในเครื่องจะเรียกเฉพาะรายละเอียดของงานที่สร้างเสียงสำเร็จผ่านคำขอที่อนุญาตจากหน้าเว็บเดียวกัน
- ปุ่มกลับมาอ่านคิวอัตโนมัติและข้อความแนะนำเมื่อ Browser ไม่อนุญาต Auto-play ใช้ชื่อ **อ่านอัตโนมัติต่อ** เหมือนกันทุกโหมด

ช่องนี้บอกข้อความที่ **ส่งให้โมเดลสร้างเสียงจริง** ไม่ใช่ผลการรู้จำเสียงที่ตรวจว่าคำใน WAV ถูกออกเสียงตรงตามต้นฉบับหรือไม่ หากต้องตรวจเสียงที่ได้จริงยังต้องฟัง WAV ร่วมด้วย


## การอ่านต่อเมื่อสร้างมีเสียงผิดพลาด (Partial TTS Success)

ในแต่ละโหมดมีตัวเลือก **อ่านต่อเมื่อสร้างมีเสียงผิดพลาด** ในชุดการตั้งค่าคิว สามารถเปิด/ปิดและกด **บันทึกการตั้งค่าคิว/ความยาวข้อความ** เพื่อบันทึกแยกโหมดได้ ค่าตั้งต้น **ปิด** และผู้ใช้รุ่นเก่าจะได้รับค่าใหม่เป็นปิดโดยไม่ล้างการตั้งค่าคิวเดิม

| ผลการสร้างเสียง | เปิดตัวเลือก | ปิดตัวเลือก |
| --- | --- | --- |
| ทุกช่วงสำเร็จ | เล่นเสียงแล้วอ่านคิวถัดไป | เล่นเสียงแล้วอ่านคิวถัดไป |
| บางช่วงล้มเหลว แต่ยังมีเสียงสำเร็จ | เล่นเสียงที่สำเร็จตามลำดับแล้วอ่านต่อทันที | เล่นเสียงที่สำเร็จจนจบ แล้วพักคิวก่อนข้อความถัดไป |
| ทุกช่วงล้มเหลว | ข้ามข้อความนั้นและอ่านคิวถัดไปทันที | พักคิวและเก็บข้อความไว้ให้ลองใหม่ด้วยปุ่ม **อ่านอัตโนมัติต่อ** |

- งานที่เล่นเสียงบางส่วนสำเร็จ **ไม่ถูกสร้างซ้ำ** หลังการพักคิว; เมื่อกดอ่านต่อจะไปยังข้อความถัดไปตาม FIFO
- ช่องประวัติข้อความหลังแปลแสดงแต่ละช่วง พร้อมสถานะ **สำเร็จ** หรือ **ข้าม (สร้างเสียงล้มเหลว)** ของโมเดลนั้น โดยประวัติหนึ่งรายการนับเมื่อเสียงเล่นจบแล้ว
- หากล้มเหลวทุกช่วง ไม่มี WAV ที่ถือว่าอ่านสำเร็จ จึงไม่เพิ่มในประวัติที่อ่านแล้ว
- หากระบบแปลภาษา/เตรียมข้อความหรือโปรแกรมเล่นเสียงล้มเหลวด้วยสาเหตุอื่น การเปิดตัวเลือกนี้ **ไม่** หมายความว่าจะข้ามข้อผิดพลาดทุกประเภทโดยอัตโนมัติ เพื่อไม่ซ่อนปัญหาของระบบ
- การแบ่งช่วงใช้ Chunk ที่ระบบสร้างเสียงส่งเข้าโมเดลจริง ไม่ใช่การแยกตามคำศัพท์อย่างสมบูรณ์ทุกกรณี
