# TikTok LIVE (Extension) — รับคอมเมนต์จากแท็บ Chrome ที่ผู้ใช้เลือก

**สถานะ:** Development Preview ใน Source Project; ยังไม่รวมใน Windows Portable Release v0.4.4 · ผู้ใช้ยืนยันว่าโหมด Extension รับคอมเมนต์ TikTok LIVE ได้แล้ว แต่การแยกเลเวล/ยศ/ป้ายและ Gift Event รุ่นใหม่ยังต้องทดสอบกับไลฟ์จริง

โหมดนี้มาแทน **TikTok LIVE (Browser)** ที่เคยเปิด Chrome ผ่าน CDP แล้วแสดง `Comments off` ขณะที่ Chrome Incognito ปกติเห็นคอมเมนต์ มีวัตถุประสงค์เพื่อลองรับข้อความจาก Chrome ที่ผู้ใช้เปิดเอง โดย **ไม่สั่งเปิด Browser ใหม่, ไม่สั่งล็อกอิน, ไม่ใช้ CDP และไม่พยายามหลบระบบป้องกัน TikTok**

## หลักการทำงาน

ผู้ใช้เลือกแท็บ TikTok LIVE ใน Chrome → กดไอคอนส่วนเสริมที่ติดตั้งเอง → ส่วนเสริมขอสิทธิ์เฉพาะแท็บนั้นผ่าน `activeTab` + `scripting` → อ่านเฉพาะ DOM ของคอมเมนต์ใหม่ → ส่งข้อความให้ extension service worker → POST ด้วย token ชั่วคราวไป `http://127.0.0.1:8765/v1/extension/messages` → SourceManager → Filters → TTS Queue → OBS Subtitle

ส่วนเสริมไม่ส่งข้อมูลไปเซิร์ฟเวอร์อื่น ไม่ดึง TikTok API ภายใน ไม่ดัก Network/WebSocket ไม่อ่านรหัสผ่านหรือคุกกี้ ไม่ใช้ `debugger` ไม่ทำการกดไลก์หรือส่งแชท และไม่อ่านข้อความเก่าที่มีอยู่ก่อนเริ่มเชื่อมต่อ Gift จะถูกแยกเป็นเหตุการณ์ต่างหากเมื่อหน้า DOM มีข้อมูลชัดเจน (ค่าเริ่มต้นไม่อ่าน Gift) ส่วน Follow, Join, Like และ Share ยังคงไม่ส่งเข้าคิวอ่านข้อความ

**ข้อจำกัด:** TikTok ไม่อนุญาตการดึงข้อมูลจากแพลตฟอร์มด้วยซอฟต์แวร์อัตโนมัติหากไม่ได้รับอนุญาตตามข้อกำหนดที่เกี่ยวข้อง [Terms of Service](https://t.tiktok.com/legal/page/us/terms-of-service/en) ควรใช้เฉพาะเมื่อมีสิทธิ์ที่เหมาะสมและปฏิบัติตามข้อกำหนด ส่วนเสริมนี้ไม่ใช่เครื่องมือที่ TikTok อนุมัติ ไม่สามารถรับรองว่าจะรับคอมเมนต์ได้กับทุก LIVE และไม่ควรใช้เพื่อหลบข้อจำกัดบัญชี/เข้าสู่ระบบ

## รูปแบบการอ่านข้อความแบบใหม่ (Extension v0.2.3)

หน้าโปรแกรมรวบรวมตัวเลือก **อ่านข้อความใหม่อัตโนมัติ** และ **อ่านชื่อผู้ส่งก่อนข้อความ** เข้าไว้ในหัวข้อ **กำหนดการอ่านข้อความและข้อมูลพิเศษ** ของแต่ละโหมดแล้ว พร้อมลดตัวเลือกที่เกี่ยวกับเสียงเหลือ:

- **อ่านชื่อผู้ส่งก่อนข้อความ** — เปิด/ปิดได้
- **คำนำหน้าชื่อผู้ส่ง** — ข้อความอิสระ เช่น `คุณ`, `ท่าน`, `คุณผู้ชม` หรือเว้นว่าง ไม่ใช่การแทนที่ `@` ทั่วระบบ
- **คำเชื่อมหลังชื่อผู้ส่ง** — เช่น `พิมพ์ว่า` หรือ `บอกว่า`
- **อ่านข้อความแชท** — เปิด/ปิดได้
- **อ่านกิจกรรมส่งของขวัญ** — สำหรับ TikTok Extension/TikFinity มีคำเชื่อม Gift แยก เช่น `ส่งของขวัญ` รวมชื่อ Gift และจำนวนที่ตรวจพบ

การอ่าน Level, Rank, Badge, Emoji และการเปิด/ปิดจำนวน Gift แยกเป็นรายช่อง **ไม่ได้แสดงเป็นตัวเลือกอีกแล้ว** ข้อมูลเหล่านั้นยังคงถูกเก็บเป็น Metadata เมื่อแหล่งข้อมูลแยกได้ แต่ไม่ถูกรวมไปในเสียงโดยอัตโนมัติ

**เครื่องหมาย `@` ในชื่อ YouTube (API/Browser):** มีตัวเลือก **อ่าน @ ที่นำหน้าชื่อผู้ส่ง** เฉพาะสองโหมด YouTube โดยค่าเริ่มต้น **ไม่อ่าน** เครื่องหมายดังกล่าว และปรับแยกโหมดได้ หากเปิดตัวเลือกจึงส่ง `@` ของชื่อไปให้ TTS ส่วน `@` ที่อยู่ในข้อความคอมเมนต์จะคงเดิมทุกกรณี (ก่อนการใช้กฎแทนข้อความส่วนกลาง)

**YouTube LIVE (API) และ YouTube LIVE (Browser) แยกกันได้**: ถ้าชื่อผู้ส่งคือ `@somchai`, ตั้งคำนำหน้า `คุณ` และคำเชื่อม `พิมพ์ว่า` จะอ่านเป็น `คุณ somchai พิมพ์ว่า ...` โดยเอา `@` หน้า *ชื่อผู้ส่ง* ออกเท่านั้น ไม่แก้ `@` ในคอมเมนต์ผู้ชม ตัวอย่าง `สวัสดี @friend` ยังเป็น `สวัสดี @friend` ในข้อความก่อนผ่านกฎแทนข้อความส่วนกลาง หากเคยตั้งกฎส่วนกลาง `@ → คุณ` ไว้ ให้ปิดกฎเดิมนั้นด้วยเพื่อไม่ให้กระทบคอมเมนต์ทั่วไป

การรับ Gift ของ Extension ปรับให้อ่านรูปแบบ `sent Heart Me 🧸 × 1` และ `sent Go Popular 🎉 × 2` ได้แม้เป็นแถว System/Notice หรือแถวธรรมดาที่ไม่มีองค์ประกอบ Text แบบคอมเมนต์ โดยตรวจประเภท Gift **ก่อน** ตรวจข้อความ Chat และส่งข้อมูลเป็น `kind=gift` พร้อม `gift_name` และ `gift_count` แยกกัน ค่าเริ่มต้นของการตั้งค่าใหม่คือเปิดอ่าน Gift; ค่าที่ผู้ใช้เคยบันทึกว่าปิดไว้จะไม่ถูกเปลี่ยนให้เอง

**การทดสอบ:** Chrome จริงกับ DOM HTML จำลองตรวจสอบการแยก Gift ทั้งสองรูปแบบ และไม่ตีความคอมเมนต์ธรรมดาที่พิมพ์ `sent Heart Me × 3` เป็น Gift โดยไม่มีหลักฐานเพิ่มเติม การใช้งานกับ TikTok LIVE จริงยังต้องยืนยันความเข้ากันได้กับ DOM ในเวลานั้น

**ติดตั้งการแก้ไข:** กด Reload ที่ `chrome://extensions` ให้เป็น **v0.2.3**, รีเฟรชแท็บ TikTok LIVE, รีสตาร์ต `Start-Dev.cmd` และรีเฟรชหน้า VoxWeaveTTS จากนั้นสร้างรหัสจับคู่ใหม่แล้วเชื่อมต่ออีกครั้ง เปิดหัวข้อการอ่านข้อความเพื่อดูว่าตัวเลือก Gift ถูกเปิดไว้หรือไม่

> ส่วนต่อไปเป็นบันทึกความสามารถและการออกแบบของรุ่นก่อนหน้า สำหรับวิธีตั้งค่าล่าสุดให้ใช้คำอธิบาย v0.2.3 ด้านบน

## ระบบอ่านข้อมูลแบบแยกประเภท (Extension v0.2.0)

**วิธีทดลองการอัปเดตนี้**: เปิด `chrome://extensions` กด **Reload** ส่วนเสริมให้เป็น v0.2.0 แล้ว **รีเฟรชแท็บ TikTok LIVE** เพื่อหยุดสคริปต์รุ่นเก่า จากนั้นรีสตาร์ต `Start-Dev.cmd`, รีเฟรชหน้า VoxWeaveTTS และกดสร้างรหัสจับคู่ใหม่ หลังเชื่อมต่อให้เปิด **กำหนดการอ่านข้อความและข้อมูลพิเศษ** ใน Tab TikTok LIVE (Extension) เลือกสิ่งที่จะอ่าน แล้วกดบันทึก

ฟีเจอร์นี้ทำงานกับ **ข้อมูลที่อ่านได้จาก DOM เท่านั้น** โดยแบ่งออกเป็นข้อมูลดังนี้:

| ข้อมูล | การใช้งาน | ค่าเริ่มต้นสำหรับ TTS |
| --- | --- | --- |
| ข้อความคอมเมนต์ | อ่านข้อความที่ผู้ชมพิมพ์ | เปิด |
| ชื่อผู้ส่ง | อ่านก่อนข้อความเมื่อเลือก Checkbox เดิม **อ่านชื่อผู้ส่งก่อนข้อความ** | ปิด |
| เลเวล (Level) | อ่านเป็น "เลเวล 25" เฉพาะเมื่อมีหมายเลขชัดเจน | ปิด |
| ยศ/อันดับ (Rank) | อ่านเป็น "อันดับ 3" เฉพาะเมื่อแยกข้อมูลได้ | ปิด |
| ป้ายสมาชิก/เหรียญตรา (Badge) | อ่านป้ายที่มีชื่อข้อความ เช่น "ป้าย InvT" | ปิด |
| ชื่อของขวัญ (Gift) | อ่าน Gift Event แยกจากคอมเมนต์ | ปิด |
| จำนวนของขวัญ | อ่าน "จำนวน 2" ต่อท้ายชื่อของขวัญ | เปิด แต่มีผลเมื่อเปิดอ่านของขวัญ |
| อีโมจิในชื่อผู้ส่ง | เลือกว่าจะอ่านอีโมจิในชื่อ เช่น 🥒Sprite Pam🥒 หรืออ่านเฉพาะตัวอักษร | ปิดสำหรับ TikTok |

**ตัวอย่าง:** เมื่อเลือกอ่านชื่อผู้ส่งและตั้งคำเชื่อมเป็น `กล่าวว่า` จะได้ `Sprite Pam กล่าวว่า สวัสดีครับ` ส่วนเมื่อเปิดเลเวล/ยศ/ป้ายเพิ่ม อาจได้ `Sprite Pam เลเวล 25 อันดับ 3 ป้าย InvT กล่าวว่า สวัสดีครับ` หาก DOM มีข้อมูลครบจริง

### เปลี่ยนคำเชื่อมและเลือกสิ่งที่จะอ่าน

ใน VoxWeaveTTS ให้เปิด Tab **YouTube LIVE (API)**, **YouTube LIVE (Browser)**, **TikTok LIVE (Extension)** หรือ **TikTok LIVE (TikFinity)** แล้วขยายหัวข้อ **กำหนดการอ่านข้อความและข้อมูลพิเศษ** ที่อยู่ใกล้ต้นหน้า

- กรอก **คำเชื่อมหลังชื่อผู้ส่ง** เช่น `พิมพ์ว่า`, `กล่าวว่า`, `บอกว่า` หรือเว้นว่างเพื่อไม่อ่านคำเชื่อม (ค่าเริ่มต้น `พิมพ์ว่า`)
- สำหรับ TikTok เลือกได้ว่าจะอ่านข้อความแชท, Gift, เลเวล, อันดับ, ป้ายสมาชิก, จำนวนของขวัญ และอีโมจิที่อยู่ในชื่อผู้ส่งหรือไม่
- ตั้ง **คำเชื่อมเมื่อได้รับของขวัญ** เช่น `ส่งของขวัญ` หรือ `มอบของขวัญ` (ค่าเริ่มต้น `ส่งของขวัญ`)
- เปิด Checkbox **อ่านชื่อผู้ส่งก่อนข้อความ** ซึ่งเป็นตัวเลือกอิสระจากคำเชื่อมและการอ่านป้าย
- ตรวจประโยคในช่อง **ตัวอย่างแชท/ของขวัญ** แล้วกด **บันทึกรูปแบบการอ่าน** เพื่อเก็บลง `data/settings/mode-voices.json`

**การตั้งค่าแยกแต่ละโหมด**: การแก้คำว่า `พิมพ์ว่า` ใน YouTube จะไม่เปลี่ยน TikTok และตัวเลือกอ่าน Gift ของ TikTok Extension ไม่เปลี่ยน TikFinity การเปลี่ยนค่าจะมีผลกับงานเสียงที่เริ่มสร้างใหม่ ไม่เปลี่ยน WAV ที่กำลังเล่น ส่วนไฟล์ตั้งค่าก่อนหน้ายังอ่านได้ตามเดิม

### ของขวัญและข้อความพิเศษ

ตัวอ่าน Extension v0.2.0 ตรวจข้อความลักษณะ `sent Heart Me × 1` เฉพาะเมื่อเข้าเงื่อนไขว่าเป็น **Gift Notification** ตาม DOM โดยส่งชนิด `gift`, ชื่อของขวัญ และจำนวนเป็นข้อมูลคนละช่อง ไม่รวมเข้าไปในข้อความแชท กรณีระบุ Gift ไม่ได้แน่ชัดจะ **ไม่เดาว่าเป็นของขวัญ** เพื่อป้องกันข้อความผิดประเภท

โหมด **TikFinity** ใช้ Event `gift`, `giftName` และ `repeatCount` ที่ผู้ให้บริการระบุ และพยายามไม่อ่านจำนวนระหว่างช่วง Gift Streak ซ้ำ โดยไม่ส่งเข้าคิวในช่วง `repeatEnd=false` และรอเหตุการณ์สุดท้ายของ Gift Streak [เอกสาร TikFinity Event API](https://tikfinity.zerody.one/tiktok/chatbot)

**ข้อจำกัด:** DOM ของ TikTok ไม่ใช่ API ที่รับประกันโครงสร้าง ป้ายที่เป็นเพียงรูปภาพไม่มีข้อความหรือไอคอนที่อ่านชื่อไม่ได้จะถูกข้าม ประเภท Gift ที่แยกไม่ได้ก็จะถูกข้ามเช่นกัน หาก TikTok เปลี่ยนตัวเลขจำนวนของขวัญในรายการเดิมระหว่าง Gift Streak ตัวอ่าน Extension อาจยังไม่ได้จำนวนสุดท้าย (ระบบป้องกันการอ่านรายการเดิมซ้ำ); ส่วน TikFinity จะใช้จำนวนที่ผู้ให้บริการแจ้งเมื่อจบ Streak ระบบไม่อนุมานระดับ/ยศจากสีไอคอน และยังไม่ยืนยันความถูกต้องของการจำแนกของขวัญหรือเหรียญตรากับ LIVE จริง

## การติดตั้งส่วนเสริมแบบ Unpacked (ยังไม่เผยแพร่ Chrome Web Store)

1. เปิด **Google Chrome** ปกติ แล้วเข้า `chrome://extensions`
2. เปิด **Developer mode** (โหมดนักพัฒนาซอฟต์แวร์)
3. กด **Load unpacked** และเลือกโฟลเดอร์นี้ทั้งโฟลเดอร์:
   `T:\Space\Projects\ProjectsProgram\VoxWeaveTTS\extensions\tiktok-live-connector`
4. หากต้องการเปิด LIVE ใน **Chrome Incognito** ให้เข้า **Details** ของส่วนเสริมและเปิด **Allow in Incognito** ด้วยตนเองก่อน (ไม่ได้เปิดโดยอัตโนมัติ) ระมัดระวังสิทธิ์ส่วนเสริมในโหมดไม่ระบุตัวตน
5. เปิดแท็บ LIVE ที่คุณมีสิทธิ์เข้าถึงในรูปแบบ `https://www.tiktok.com/@username/live` และตรวจว่า Chrome ปกติแสดงข้อความคอมเมนต์ได้

## การเชื่อมต่อกับ VoxWeaveTTS

1. ปิดแล้วเปิด Source Project ด้วย `Start-Dev.cmd` ใหม่ และรีเฟรชหน้า Web UI
2. เข้า Tab **TikTok LIVE (Extension)** (โหมดภายในยังชื่อ `tiktok_browser` เพื่อคงการตั้งค่าเดิม)
3. กรอก Username/URL ของ LIVE ให้ตรงกับแท็บ Chrome ตั้ง Filter และ Voice ได้ตามปกติ
4. กด **สร้างรหัสจับคู่** โปรแกรมจะสร้างรหัสแบบใช้ครั้งเดียว มีอายุ 5 นาที
5. กด **คัดลอกรหัส** แล้วกลับไปที่แท็บ LIVE ใน Chrome กดไอคอน **VoxWeaveTTS — TikTok LIVE Extension**
6. กรอก Port (ปกติ `8765`) และวางรหัส แล้วกด **เชื่อมต่อแท็บนี้**
7. ตรวจสถานะในหน้า VoxWeaveTTS: รอจับคู่ → Extension เชื่อมต่อ → รอ DOM Chat → พร้อมรับข้อความใหม่
8. หยุดได้จากปุ่ม **หยุดรับข้อความ** ใน VoxWeaveTTS หรือ **หยุดรับข้อความ** ในส่วนเสริม

สลับแท็บหน้า VoxWeaveTTS ได้โดยไม่หยุด TTS ของโหมดอื่น หากปิดแท็บ TikTok, ปิด Chrome, เปลี่ยนห้อง LIVE, หรือ Browser ปิด Service Worker แล้วตัวเชื่อมต่อขาด ให้กด **สร้างรหัสจับคู่ใหม่** เพื่อเริ่ม session ใหม่

## การป้องกันข้อมูลในเครื่อง

- HTTP Server รับคำขอจากส่วนเสริมเฉพาะ Origin `chrome-extension://<extension_id>` ที่ตรงรูปแบบมาตรฐาน และ Host `127.0.0.1:<port>` เท่านั้น ไม่มี CORS สำหรับเว็บไซต์ทั่วไป
- ต้องใช้ **รหัสจับคู่ครั้งเดียว** ที่สร้างจาก Source Session ซึ่งผู้ใช้กดเริ่มเอง แล้วส่งกลับ **Session Token** แบบสุ่ม (เก็บใน `chrome.storage.session` ของส่วนเสริม ไม่บันทึกถาวร)
- Bind Token กับ Extension ID และ Username/URL ของไลฟ์เดิม ตรวจสอบทุกชุดข้อความ; จำกัดขนาด batch 20, ความยาวข้อความ 280 ตัวอักษร และคิวที่รับเข้า
- หน้า TikTok ไม่ได้รับ Token ตัวเชื่อม, รหัสจับคู่ หรือสิทธิ์เข้าถึง API ของ VoxWeaveTTS โดยตรง
- ส่งข้อความผ่าน `textContent` และรายการคิว TTS เดิม; ข้อความจากหน้า LIVE เป็นข้อมูลที่ไม่เชื่อถือ
- โหมด TikFinity เดิมและ YouTube/Discord เดิมไม่ได้รับผลกระทบ

## การอัปเดตส่วนเสริมและการตรวจจับ DOM (v0.1.1)

หากเคยติดตั้ง `TikTok LIVE (Extension)` รุ่นก่อนแล้ว จะต้อง **Reload ส่วนเสริมใน Chrome** เพื่อโหลดไฟล์ `content.js` และ `background.js` ที่แก้ไข ไม่ใช่เพียงรีเฟรชหน้า VoxWeaveTTS:

1. ไปที่ `chrome://extensions` หา **VoxWeaveTTS — TikTok LIVE Extension** แล้วกดปุ่ม **Reload** (ไอคอนลูกศรวน)
2. ปิดและเปิด `Start-Dev.cmd` ใหม่เพื่อให้ Backend ใช้โค้ดปัจจุบัน
3. รีเฟรชเว็บ VoxWeaveTTS ด้วย `Ctrl+Shift+R` แล้วรีเฟรชแท็บ TikTok LIVE
4. ให้หน้า LIVE แสดงคอมเมนต์ได้ตามปกติ จากนั้นใน VoxWeaveTTS เลือก **TikTok LIVE (Extension)** แล้วกด **สร้างรหัสจับคู่ใหม่**
5. กดไอคอนส่วนเสริมในแท็บ LIVE แล้วเชื่อมต่อด้วยรหัสใหม่นั้น (ไม่ต้องเข้าสู่ระบบ TikTok ใหม่)
6. ดูบรรทัด **DOM:** ใต้สถานะของโหมด ซึ่งบอกจำนวนกล่องแชท แถวข้อความ แถวที่แยกเนื้อหาได้ และข้อความใหม่ล่าสุด
7. หากไม่มีข้อความเข้า ให้กด **คัดลอกสถานะตรวจจับ (ไม่รวมข้อความแชท)** แล้วส่งผลให้ตรวจสอบ แสดงเพียงจำนวนและสถานะ ไม่ส่งข้อความหรือชื่อผู้ชม

ตัวอ่านปรับเพิ่มการตรวจแถวคอมเมนต์ที่อยู่ใต้ `[data-e2e="live-chat-container"]` และกรณีที่แถวเป็น `div` ทั่วไปโดยมีชื่อผู้ส่งและข้อความแยกกัน ไม่ยึดเฉพาะ CSS Class เดิม ซึ่งโครงสร้าง TikTok อาจเปลี่ยนได้อีก

**แปลผลสถานะ DOM**
- **กล่องแชทไม่พบ:** หน้า LIVE ยังไม่โหลดแชทหรือ TikTok เปลี่ยนโครงสร้างระดับกล่อง
- **กล่องแชทพบ แต่แถวคอมเมนต์ 0:** ตัวอ่านหาแถวไม่เจอ หรือช่วงนั้นยังไม่มีข้อความปรากฏ
- **แถวคอมเมนต์มากกว่า 0 แต่แยกข้อความได้ 0:** โครงสร้างชื่อผู้ส่งหรือเนื้อหาต่างจากตัวอ่าน
- **แยกข้อความได้มากกว่า 0 แต่ใหม่ล่าสุด 0:** อาจเป็นประวัติที่แสดงอยู่ก่อนกดเชื่อมต่อ หรือไม่มีข้อความใหม่ในรอบนั้น
- **ข้อความใหม่มากกว่า 0 แต่ Backend รับ 0:** ตรวจการเชื่อมต่อและตัวกรองใน VoxWeaveTTS

## Chrome แจ้ง `Extension context invalidated` (แก้ใน v0.1.2)

ข้อผิดพลาดนี้เกิดเมื่อ Chrome ยังเปิดแท็บ TikTok ที่มี `content.js` ของส่วนเสริม **รุ่นก่อน Reload** อยู่ แม้ตัวส่วนเสริมจะโหลดรุ่นใหม่แล้วก็ตาม สคริปต์เก่าอาจยังเรียก `chrome.runtime.sendMessage` ผ่าน Context ที่ถูกยกเลิก จึงเกิด Error ซ้ำในหน้า `chrome://extensions`

**ขั้นตอนหลังอัปเดตส่วนเสริมทุกครั้ง:**
1. เปิด `chrome://extensions` และกด **Reload** ที่ส่วนเสริม **VoxWeaveTTS — TikTok LIVE Extension** ให้แสดงรุ่น **0.1.2** หรือใหม่กว่า
2. กลับไปแท็บ TikTok LIVE แล้ว **รีเฟรชแท็บนั้น** ด้วย `Ctrl+R` เพื่อยุติสคริปต์เก่าที่โหลดอยู่ในหน้า (การ Reload ส่วนเสริมอย่างเดียวไม่พอ)
3. กด **สร้างรหัสจับคู่ใหม่** ใน VoxWeaveTTS แล้วใช้ Popup ของส่วนเสริมเชื่อมต่อกับแท็บเดิมอีกครั้ง
4. ถ้า Chrome ยังแสดงปุ่ม **Errors** ให้เปิดรายการข้อผิดพลาด ตรวจเวลาเกิด และล้าง Error เก่าที่เก็บค้างไว้ ข้อความเดิมในรายการไม่ใช่หลักฐานว่ารุ่นใหม่ยังมีปัญหา

ในรุ่น 0.1.2 เพิ่มการตรวจ `chrome.runtime.id`, ดัก `sendMessage` ที่ล้มเหลวทั้งแบบ synchronous และ callback และหยุด `MutationObserver`/interval/timer เมื่อ Context ใช้ไม่ได้ **การแก้ไขนี้ไม่สามารถย้อนกลับไปเปลี่ยนสคริปต์เก่าที่โหลดอยู่ในแท็บก่อนหน้า** จึงต้องรีเฟรชแท็บ TikTok หนึ่งครั้งหลัง Reload ส่วนเสริมเสมอ

ข้อผิดพลาดนี้เป็นปัญหาการเชื่อมต่อของ Chrome Extension ไม่ได้ยืนยันว่าตัวอ่าน DOM รับคอมเมนต์ LIVE จริงได้แล้ว หากยังรับข้อความไม่ได้ ให้ดูบรรทัด **DOM:** ใน VoxWeaveTTS หลังเชื่อมต่อใหม่

## การอ่านคอมเมนต์ที่มีหรือไม่มีป้าย และรับข้อความขณะแท็บอยู่เบื้องหลัง (v0.2.1)

ตัวอ่านไม่สมมติว่าผู้ชมทุกคนต้องมีเลเวล ยศ หรือป้ายครบทุกชนิดอีกต่อไป โดยใช้ **ชื่อผู้ส่งเป็นจุดอ้างอิงของแถวข้อความเดียวกัน** และพยายามอ่านส่วนท้ายสุดเป็นคอมเมนต์ แยกการอ่านข้อมูลพิเศษเฉพาะเมื่อ DOM ระบุได้จริง

- รองรับรายการแบบมี **เลเวล/ยศ/ป้ายครบ**, มี **เฉพาะบางป้าย**, หรือ **ไม่มีข้อมูลพิเศษเลย**
- รองรับคอมเมนต์ทั้งแบบแยกบรรทัดใต้ชื่อและแบบอยู่บรรทัดเดียวกับชื่อ โดยไม่เอาแถวผู้ชมหลายคนมารวมกัน
- กรณี TikTok ใช้ DOM แถวเดิมซ้ำกับข้อความใหม่ ตัวอ่านจะใช้เอกลักษณ์ของข้อความเพื่อไม่ทิ้งคอมเมนต์ใหม่เพียงเพราะเป็น HTML Element เดิม (ของขวัญในสตรีกเดิมจะยังถูกกันซ้ำ)
- เมื่อแท็บไม่อยู่ในโฟกัส Chrome อาจลดความถี่ `setTimeout`/`setInterval` ตัวอ่านเปลี่ยนให้ **DOM MutationObserver ส่งสัญญาณประมวลผลผ่าน microtask** โดยไม่รอ Timer 500 มิลลิวินาทีเหมือนก่อน และจะตรวจซ้ำเมื่อกลับเข้าแท็บ
- ขยายช่วงผ่อนผันของ Heartbeat ส่วนเสริมจาก 15 เป็น 90 วินาที เพื่อไม่ให้ระบบรายงานว่า Extension หลุดเพราะ Chrome หน่วง Timer เบื้องหลังเพียงชั่วคราว

หน้า VoxWeaveTTS และ Popup Extension จะแสดงข้อมูลวินิจฉัยเพิ่ม เช่น **แท็บแสดงอยู่/อยู่เบื้องหลัง**, **อยู่ในโฟกัสหรือไม่**, และ **DOM แชทไม่เปลี่ยนมากี่วินาที** ถ้าไม่มี DOM เปลี่ยนเป็นเวลานานในแท็บเบื้องหลัง นั่นเป็นเพียง *สัญญาณ* ว่าหน้าเว็บอาจไม่อัปเดต ไม่ใช่หลักฐานว่าเจ้าของ LIVE ปิดแชท

**ข้อจำกัดสำคัญ:** ส่วนเสริมอ่านข้อความได้เฉพาะที่ TikTok แสดงใน DOM เท่านั้น ถ้า TikTok หยุดส่งหรือหยุดวาดคอมเมนต์ระหว่างแท็บถูกซ่อนจริง ๆ ส่วนเสริมไม่สามารถเรียกคืนคอมเมนต์ที่เว็บไซต์ไม่ได้แสดง และไม่ควรพยายามหลบข้อจำกัดของ TikTok หากต้องการทดสอบการรับแบบต่อเนื่อง ให้เปิดแท็บ LIVE ในหน้าต่าง Chrome ที่ยังแสดงอยู่โดยไม่จำเป็นต้องคลิกโฟกัสตลอด และหลีกเลี่ยงการให้ระบบพักแท็บระหว่างการทดลอง

**วิธีอัปเดต:** กด Reload ส่วนเสริมที่ `chrome://extensions` ให้แสดง **v0.2.1**, **รีเฟรชแท็บ TikTok LIVE** เพื่อหยุด Content Script เก่า จากนั้นรีสตาร์ต `Start-Dev.cmd`, รีเฟรชหน้า VoxWeaveTTS, สร้างรหัสจับคู่ใหม่แล้วเชื่อมต่อใหม่

## แยกอันดับ `No. 2` ออกจากข้อความคอมเมนต์ (v0.2.2)

แก้กรณี TikTok แสดงป้ายอันดับ `No. 2` ต่อท้ายชื่อผู้ส่ง แต่ DOM รายงานบรรทัดอันดับเป็นส่วนหนึ่งของข้อความ เช่น `maitreewongthawik: No. 2 Trum up Trum up!!`

วิธีแยกในรุ่นนี้:
- ให้ความสำคัญกับ **องค์ประกอบ DOM ของข้อความคอมเมนต์จริง** ก่อนอ่านข้อความ `innerText` ของแถวทั้งหมด
- ถ้าไม่มีตัวระบุข้อความที่เชื่อถือได้ จึงอ่านองค์ประกอบข้อความท้ายแถวที่ไม่ใช่ชื่อผู้ส่ง เลเวล อันดับ หรือป้าย
- ถ้ายังต้องใช้ `innerText` เป็นทางสำรอง ให้ตัดบรรทัดป้ายอันดับที่แยกเป็นบรรทัดของตัวเองก่อนคอมเมนต์ และตัดคำนำหน้า `No. 2` ที่ติดอยู่กับข้อความเฉพาะเมื่อ **ตรวจพบป้ายอันดับหมายเลขเดียวกันจาก DOM แยกต่างหาก** เท่านั้น
- ไม่ตัดคำว่า `No. 2` ในกรณีที่ผู้ชมพิมพ์เองเป็นเนื้อหาคอมเมนต์ โดยเฉพาะเมื่อพบองค์ประกอบข้อความจริงโดยตรง
- ไม่บังคับว่าผู้ชมต้องมีเลเวล อันดับ หรือป้าย และยังไม่รวมแถวข้อความหลายคนเป็นรายการเดียว

ตัวอย่างที่ตรวจด้วย Chrome บน **หน้า HTML จำลอง**: ป้าย `No. 2` + คอมเมนต์ `Trum up Trum up!!` จะอ่านเฉพาะคอมเมนต์ ส่วนคอมเมนต์ `No. 2 เป็นชื่อเพลงที่ชอบ` จะเก็บข้อความครบ

**อัปเดต:** ไปที่ `chrome://extensions` กด Reload ให้เป็น **v0.2.2** แล้วรีเฟรชแท็บ TikTok LIVE ด้วย `Ctrl+R` จากนั้นเชื่อมต่อส่วนเสริมใหม่ด้วยรหัสจับคู่ใหม่จาก VoxWeaveTTS

เนื่องจาก DOM ของ TikTok อาจเปลี่ยน การทดสอบ HTML จำลองไม่ใช่การยืนยันว่ารับข้อมูลทุกกรณีจาก LIVE จริงได้ หากยังพบข้อมูลอันดับปนเข้าคอมเมนต์ ให้ตรวจรูปแบบ DOM ที่หน้า LIVE เฉพาะกรณีนั้นก่อนปรับ Selector เพิ่ม

## ถ้าเชื่อมต่อไม่ได้

- **ไม่เห็นรหัสจับคู่:** รีสตาร์ต Backend และรีเฟรชหน้า Web UI, กดสร้างรหัสอีกครั้ง
- **Pairing rejected:** รหัสหมดอายุหรือถูกใช้แล้ว, เลือก LIVE คนละช่อง, เปลี่ยนโหมด หรือพอร์ตผิด ให้เริ่มการจับคู่ใหม่
- **Extension ยังไม่พบ DOM Chat:** ตรวจสอบว่า LIVE ยังดำเนินอยู่ และมีรายการคอมเมนต์ในแท็บนั้น TikTok อาจปรับ DOM จน Selector ไม่ตรง
- **Comments off:** เป็นสถานะในแท็บนี้เท่านั้น ไม่พิสูจน์ว่าเจ้าของไลฟ์ปิดการแชท
- **Maximum number of attempts reached:** หยุดลองล็อกอินซ้ำและอย่าพยายามหลบระบบจำกัดของ TikTok
- **ไม่มีส่วนเสริมใน Incognito:** เปิด Allow in Incognito ให้ส่วนเสริมด้วยตัวเอง
- **ส่วนเสริมหลุดหลังเปลี่ยน LIVE/ปิดแท็บ:** กดสร้างรหัสจับคู่ใหม่ แล้วเชื่อมต่อบนแท็บที่ต้องการ
