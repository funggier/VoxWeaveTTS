# VoxWeaveTTS v0.12.4 — กฎข้อความซ้ำ อิโมจิ YouTube/Discord/TikTok และคิว Live

**Windows x64 Portable Core ครบชุด** · Universal `.vwmodel` **Format V4 เท่านั้น** · ใช้งานแบบย้ายโฟลเดอร์ได้ · **ไม่แนบโมเดลเสียงหรือน้ำหนักโมเดล**

## เพิ่มจาก v0.12.3

### กฎแทนคำ ข้ามคำ และข้อความซ้ำ
- เพิ่ม `match_mode: repeat_run` สำหรับกลุ่มอักขระหรือสัญลักษณ์ติดกัน เช่น `www`, `55555`, `😂😂😂`
- เพิ่ม `match_mode: phrase_run` สำหรับคำหรืออิโมจิซ้ำที่คั่นด้วยช่องว่าง เช่น `หน้าหัวเราะ หน้าหัวเราะ หน้าหัวเราะ` และ `😂 😂 😂`
- กำหนด `min_repeats` **2–1,000 ครั้ง** และทำหลายระดับ 3, 5, 7 ได้พร้อมกัน โดยใช้เกณฑ์สูงสุดที่ตรงกับทั้งกลุ่ม ไม่แบ่งเป็นหลายส่วนย่อย
- วลีซ้ำแบบ Replace ที่เว้นคำอ่านแทนว่างจะอ่านวลีเพียงหนึ่งครั้ง; ต้นฉบับยังคงใช้แสดงผล/Subtitle
- โหมด `skip` ช่วยไม่อ่านเฉพาะส่วนที่ตรงเงื่อนไข และ `sources` จำกัดให้มีผลเฉพาะช่องทาง Live ได้
- เพิ่มตัวเลือกทั้งสองรูปแบบลงใน **กฎการอ่านส่วนกลาง → เพิ่มกฎอย่างรวดเร็ว** และคงความเข้ากันได้กับ `literal` / `five_run` เดิม

### อิโมจิ YouTube, Discord และ TikTok
- **Unicode มาตรฐาน:** อิโมจิทั่วไป, variation selectors, ZWJ, โทนสีผิว และอิโมจิที่มีรูปแบบ Unicode ต่างกัน ใช้พจนานุกรมคำอ่านต่อโหมดได้ โดยค่าเฉพาะอิโมจิมีสิทธิ์สูงกว่า fallback
- **YouTube LIVE API / Browser:** ชื่ออิโมจิสำเร็จรูป เช่น `:yt:`, `:face-blue-smiling:`; Browser อ่านชื่อจากรูปอิโมจิภายในคอมเมนต์และปรับชื่อภาษาอังกฤษตัวพิมพ์เล็กที่ไม่มี `:` เป็น `:name:`
- **Discord Bot / Client:** อิโมจิ Unicode และอิโมจิเฉพาะเซิร์ฟเวอร์ `<:name:id>` / `<a:name:id>` โดยใช้ `:name:` เพื่อกำหนดคำอ่านได้
- **TikTok LIVE (TikFinity) / TikTok LIVE (Extension):** อิโมจิ Unicode และรหัส TikTok `[smile]`, `[laughwithtears]`, `[cry]`; ตั้งชื่อสำรองแบบ `:smile:` ได้ (หากตั้ง `[smile]` โดยตรงจะมีสิทธิ์สูงกว่า) ส่วน Extension ใช้ข้อความจาก `alt`/ชื่อสำหรับผู้ใช้ของรูปภาพในเนื้อหาคอมเมนต์เท่านั้น
- คำหรืออิโมจิที่ไม่มี Mapping **คงเดิม**; ไม่แปลงคำธรรมดาเป็นอิโมจิและไม่อ่านรูปภาพของขวัญ/Badge/สติกเกอร์ของ Discord หรือ TikTok; TikTok อาจไม่แสดงชื่ออิโมจิพิเศษในทุกเส้นทาง Live
- พจนานุกรมอิโมจิเปิดใช้งานเองและแยกโหมด (สูงสุด **64 รายการต่อโหมด**); ประวัติข้อความแชทต้นฉบับไม่ถูกแก้

### คิว Live และการรับมือข้อผิดพลาด
- ขยายความจุ **เตรียมข้อความ/AI ล่วงหน้า 1–100 ข้อความ** และ **เสียงรออ่าน/สร้าง 1–20 งาน** แยกต่อโหมด (ค่าเริ่มต้น 3/2); ไม่มีเพดานผลรวม 10 งานแบบ v0.12.3 แล้ว
- กำหนดระยะเวลา **รอประมวลผลเสียง 1–60 นาทีต่อข้อความ** (เริ่มต้น 4 นาที); เวลารอช่องสร้างเสียงไม่คิดรวมเวลาประมวลผล
- ตัวเลือก **อ่านต่อเมื่อเกิดความผิดพลาด** ข้ามงานแปลหรือสร้างเสียงที่ล้มเหลว/หมดเวลา แล้วอ่านตาม FIFO ต่อโดยไม่ข้ามงานที่กำลังดำเนินการ
- เพิ่ม **บังคับเล่นเสียงต่ออัตโนมัติ** (ปิดเป็นค่าเริ่มต้น) สำหรับ **ข้าม WAV ที่ Browser ปฏิเสธการเล่น** และไปคิวต่อไป โดยไม่จำกัดจำนวนครั้ง พร้อมตัวนับข้อความที่ถูกข้าม ไม่ใช่การปลดล็อกสิทธิ์ Autoplay; หาก Browser บล็อกทุกเสียง ข้อความทั้งหมดอาจถูกข้ามโดยไม่มีเสียงออกมา
- สถานะ Live แสดงข้อมูลแยกสำหรับการรับข้อความ การเตรียมข้อความ สร้าง WAV คิวเสียง และงานอ่านแล้ว
- การตั้งค่าคิวเดิมถูกย้ายเป็นรูปแบบใหม่โดยไม่ลบค่าที่บันทึกไว้; ระบบยังรักษาลำดับ FIFO และจำกัดแคช WAV รวม 512 MB / งานกลางสูงสุด 768 รายการ

## วิธีอัปเดต
1. ปิด VoxWeaveTTS ที่กำลังทำงานและสำรอง `data/`, `config/`, `presets/`, `models/` และ `runtime/environments-v4/` จากโปรแกรมเก่า
2. แตก `VoxWeaveTTS-v0.12.4-portable.zip` ไปยังตำแหน่งใดก็ได้
3. หากต้องการใช้การตั้งค่าเก่า คัดลอกโฟลเดอร์ข้อมูลและโมเดลที่สำรองไว้เข้าสู่ตัวโปรแกรมใหม่โดยไม่ทับซอร์สและไฟล์ Core; จากนั้นเรียก `VoxWeaveTTS.exe`
4. หากใช้ **TikTok LIVE (Extension)** ให้ Reload Extension จาก `extensions/tiktok-live-connector/` ผ่านหน้า Extensions ของ Browser เพื่อใช้ตัวอ่านใหม่

**ข้อจำกัด:** การอ่านอิโมจิขึ้นกับข้อความ/รหัสที่แต่ละแพลตฟอร์มส่งมาจริง และไม่รับประกันการเล่นเสียงหาก Browser ไม่อนุญาต Autoplay

TikTok Extension v0.2.6 มีไฟล์ ZIP แยกสำหรับแตกติดตั้งแบบ Unpacked: VoxWeaveTTS-TikTok-Extension-v0.2.6.zip
