# VoxWeaveTTS v0.12.10 — อ่านแชทในแท็บเบื้องหลัง และแก้การเล่นเสียงผ่าน LAN

## ดาวน์โหลด

- **Windows Portable x64** ดาวน์โหลด `VoxWeaveTTS-v0.12.10-portable.zip` จาก Assets แตกไฟล์ แล้วเปิด `VoxWeaveTTS.exe` หรือ `Start-Console.cmd`
- **โมเดล** [ดาวน์โหลดแพ็กเกจโมเดล `.vwmodel` v4 ทั้ง 7 แพ็กเกจ](https://github.com/funggier/VoxWeaveTTS/releases/tag/v0.12.1-modelpacks-v4) ตัวโปรแกรมรองรับแพ็กเกจ v4 ที่ติดตั้งไว้เดิม และดาวน์โหลดโมเดลแยกตามสัญญาอนุญาตของแต่ละแพ็กเกจ
- **ตรวจสอบไฟล์** ใช้ `SHA256SUMS-v0.12.10.txt` ใน Assets เทียบ SHA-256 ของ ZIP

## สิ่งที่แก้

- เมื่อเปิด **เตรียมเสียงล่วงหน้า** โปรแกรมรอแจ้งสถานะงานจากเซิร์ฟเวอร์ผ่าน SSE โดยใช้ช่องเดียวต่อหน้าเว็บสำหรับโหมด Live ทั้งหมด งานเดินต่อเมื่อเตรียมข้อความหรือสร้างเสียงเสร็จ และเล่นตามลำดับเดิม
- เมื่อช่องแจ้งสถานะเชื่อมต่อใหม่ โปรแกรมอ่านสถานะงานที่ติดตามอีกครั้ง การตรวจสถานะเป็นช่วงยังใช้เป็นทางสำรองหากช่องแจ้งสถานะใช้ไม่ได้
- แก้ `crypto.randomUUID is not a function` สำหรับหน้าเว็บ HTTP บน LAN และ Tailnet รหัสเซสชันเล่นเสียงใช้ `crypto.getRandomValues()` และรักษารูปแบบ UUID v4 เดิม
- [คู่มือเครือข่ายภาษาไทย](https://github.com/funggier/VoxWeaveTTS/blob/v0.12.10/docs/NETWORK_TH.md) อธิบายวิธีเลือก IPv4/พอร์ต การตั้งรหัสผ่านจาก Command Prompt และตัวอย่าง `Start-Console.cmd` แบบเต็มสำหรับการดับเบิลคลิก

## การใช้งานและขอบเขต

ในหน้า Live ให้เปิด **อ่านอัตโนมัติ** และ **เตรียมเสียงล่วงหน้า** ได้ตามที่ต้องการ

ในเครื่องทดสอบ Windows ใช้ Chrome ผ่าน LAN HTTP กับข้อความและ WAV จำลอง หลังเล่นเสียงแรกขณะมองเห็นแท็บ โปรแกรมอ่าน 4 ข้อความตามลำดับหลังสลับแท็บ และอีก 2 ข้อความขณะย่อหน้าต่าง เมื่อจำลองให้ Timer ในแท็บซ่อนรออย่างน้อย 4 วินาที ข้อความทดสอบหนึ่งรายการเล่นจบในประมาณ 0.9 วินาทีผ่านการแจ้งสถานะจากเซิร์ฟเวอร์ ตัวเลขนี้เป็นผลจากชุดจำลอง

เบราว์เซอร์ยังเป็นตัวเล่นเสียงและควบคุมสิทธิ์เล่นเสียงอัตโนมัติ ในรอบที่ซ่อนแท็บก่อนมีเสียงรายการแรก Chrome ในชุดทดสอบยังไม่ได้โหลดเสียงจนกลับมาที่แท็บ จากนั้นจึงเล่นเสียงจบ กรณีเบราว์เซอร์พักแท็บทั้งหน้า การเล่นเสียงจะรอให้แท็บกลับมาทำงาน
