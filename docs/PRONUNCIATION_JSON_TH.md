# การตั้งค่าคำอ่านด้วย JSON — VoxWeaveTTS

> สำหรับช่อง **Rules** และ **Pronunciations** ที่มีอยู่ในหน้าเว็บ ไม่ใช่การเปิดเอกสาร JSON เพื่อให้ TTS อ่าน

## วิธีใช้

ช่องทั้งสองยังเป็น JSON ที่แก้ได้โดยตรง แต่มีเครื่องมือช่วย:

- **จัดรูปแบบ**: จัดย่อหน้าและเว้นวรรค 2 ช่องให้ดูง่าย โดยไม่สลับลำดับ Rules
- **ตรวจ JSON**: ตรวจไวยากรณ์และชนิดข้อมูลที่ระดับบนสุด (Rules = Array, Pronunciations = Object); การตรวจเงื่อนไขละเอียดให้กด **ทดลองประมวลผลข้อความ** เพื่อทดสอบผ่าน Backend จริง
- **บันทึกไฟล์**: ดาวน์โหลด rules.json หรือ pronunciations.json เก็บในเครื่อง โดยไม่ส่งไป Cloud และไม่เขียนลงไฟล์ตั้งค่าของเซิร์ฟเวอร์อัตโนมัติ
- **นำเข้าไฟล์**: เปิดไฟล์ JSON ที่เคยบันทึกจากเครื่อง แล้วแสดงในช่องแก้ไข ยังไม่บันทึกถาวรจนกดบันทึกในโปรแกรม
- **บันทึกในโปรแกรม**: ตรวจโครงสร้างและกฎจาก Backend ก่อนบันทึกลง `data/filters/rules.json` หรือ `data/dictionaries/pronunciations.json` ของโปรเจกต์แบบ Atomic
- **โหลดค่าที่บันทึก**: ดึงข้อมูลจากโปรเจกต์กลับมาแสดงอีกครั้ง (ถามก่อนเขียนทับข้อความที่กำลังแก้ไข)
- **เพิ่มรายการเร็ว**: กรอกข้อความต้นฉบับและคำอ่าน แล้วระบบสร้าง JSON พร้อม Escape อักขระให้เอง ใช้กับภาษาไทย เครื่องหมายคำพูด แบ็กสแลช และ Emoji ได้

หาก JSON ผิด ระบบจะแจ้งข้อผิดพลาดและ **ไม่แทนที่ข้อมูลที่พิมพ์ไว้**. การแก้ไขในหน้าเว็บไม่บันทึกอัตโนมัติจนกด **บันทึกในโปรแกรม**; เมื่อเปิดโปรแกรมใหม่ ข้อมูลที่เคยบันทึกจะถูกโหลดกลับมาอัตโนมัติ หากยังไม่เคยบันทึก ระบบจะแสดงกฎตัวอย่างเดิมไว้ให้แก้ไขก่อน

**ป้องกันการบันทึกทับ:** โปรแกรมส่ง Revision ของ Rules และ Pronunciations แยกกัน หากไฟล์มีการเปลี่ยนในแท็บอื่นหรือบนดิสก์ จะตอบ HTTP 409 โดยไม่เขียนทับ ให้คัดลอกข้อความที่แก้ไขไว้เทียบกับข้อมูลที่บันทึกก่อน

**ส่วนตัว:** ไฟล์ทั้งสองอยู่ใน `data/` ที่ Git Ignore ไว้ และไม่มีการอัปโหลด Cloud; ไม่รวมใน GitHub Release โดยอัตโนมัติ

## ตัวอย่าง Pronunciations (คำอ่าน)

~~~json
{
  "อมตะ": "อะ มะ ตะ",
  "เซียน": "เซียน",
  "“สวัสดี!”": "สวัสดี",
  "ฮ่า\\ฮ่า": "ฮ่า ฮ่า",
  "คำว่า \"อมตะ\"": "อะ มะ ตะ",
  "😄": "หัวเราะ"
}
~~~

คำทางซ้ายคือข้อความที่ค้นหา และด้านขวาคือข้อความที่จะส่งให้ TTS ออกเสียงแทน; **Subtitle ยังแสดงข้อความเดิม** หากไม่ได้เปลี่ยนผ่าน Rules

## ตัวอย่าง Rules (กฎการอ่านและการกรอง)

~~~json
[
  {
    "match": "คำต้องห้าม",
    "mode": "silence",
    "display": "***",
    "silence_ms": 400
  },
  {
    "match": "555",
    "match_mode": "five_run",
    "mode": "replace",
    "spoken": "ฮ่า ฮ่า ฮ่า"
  },
  {
    "match": "«คำว่า \"พิเศษ\"»",
    "mode": "replace",
    "spoken": "คำพิเศษ"
  }
]
~~~

รูปแบบ Rules มีลำดับความสำคัญตามที่ระบบประมวลผลกำหนด; เครื่องมือจัดรูปแบบจะรักษาลำดับรายการใน Array เดิม

## เครื่องหมายพิเศษใน JSON

JSON เป็นรูปแบบข้อมูลที่ต้อง Escape บางตัวเมื่อเขียนเองในช่อง Textarea:

| ต้องการใส่ | วิธีพิมพ์ในข้อความ JSON |
|---|---|
| เครื่องหมายคำพูดคู่ | \" |
| เครื่องหมายแบ็กสแลช | \\ |
| ขึ้นบรรทัดใหม่ในค่า String | \n |
| แท็บในค่า String | \t |
| วรรณยุกต์ไทย / เครื่องหมาย “ ” « » / Emoji | ใส่ตรง ๆ ภายในเครื่องหมายคำพูดได้ |

**ข้อควรจำ:** JSON ใช้เครื่องหมายคำพูดคู่สำหรับ Key และ Value; เครื่องหมายคำพูดเดี่ยวไม่สามารถใช้ครอบ JSON String แทนได้. หากใช้ช่อง **เพิ่มรายการเร็ว** ระบบ Escape ให้โดยอัตโนมัติ ไม่ต้องจำรูปแบบเหล่านี้

## อักขระพิเศษในเอกสาร TXT / Markdown

ตัวจัดเอกสารแยกการจัดรูปแบบ Markdown ออกจากข้อความที่อ่านจริง: เครื่องหมายคำพูด, Unicode, Emoji, แบ็กสแลช และวรรณยุกต์ไทยในเนื้อหาได้รับการรักษาไว้ตามโครงสร้างที่รองรับ แต่เครื่องหมายที่เป็น **Markdown Syntax** เช่นตัวคั่น Code Block, ภาพ และ URL ของลิงก์จะถูกตัดตามนโยบาย Narration Cleanup ซึ่งไม่ใช่การอ่านข้อความแบบ Lossless ทุกกรณี

การเก็บอักขระในระบบไม่ใช่การรับประกันว่า TTS Engine ทุกตัวจะ **ออกเสียง** Emoji หรือสัญลักษณ์เหมือนกัน ควรแก้การอ่านผ่าน Rules/Pronunciations และตรวจฟังกับ Engine ที่เลือก
