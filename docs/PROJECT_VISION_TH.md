> เอกสารผลิตภัณฑ์ (Product Vision & Background) · 10 พฤศจิกายน 2026  
> สถานะ: แผนและเจตนาการออกแบบ ไม่ใช่การยืนยันว่าระบบทั้งหมดพัฒนาเสร็จแล้ว  
> Repository: https://github.com/funggier/VoxWeaveTTS

## 1. ที่มาของโครงการ (Why)

VoxWeaveTTS เริ่มจากความต้องการฟังข้อความภาษาไทย โดยเฉพาะนิยายและข้อความที่ผู้อื่นส่งเข้ามา ด้วยเสียงที่ผู้ใช้ปรับให้ตรงกับความชอบได้ ไม่ใช่ถูกจำกัดด้วยเสียง TTS สำเร็จรูปที่อาจฟังแข็ง ไม่เป็นธรรมชาติ หรือไม่ตรงกับอารมณ์ของเนื้อหา

ปัญหาที่พบจากการฟังคลิปอ่านนิยาย:

1. **ออกเสียงภาษาไทยผิด** บางคำ: ตัวอย่างคำว่า **อมตะ** ควรอ่าน “อะ-มะ-ตะ” แต่บางระบบอาจอ่าน “อม-ตะ”; คำว่า **เซียน** อาจกลายเป็นเสียง “เซี่ยน” การแก้วรรณยุกต์และการเว้นพยางค์ต้องทดลองกับเสียงจริง ไม่ใช่เพียงแก้สตริง
2. **เนื้อเสียงไม่ถูกใจ** แม้คำถูกต้อง ก็อาจไม่เหมาะกับนิยายหรือลักษณะการรับฟังของแต่ละคน จึงต้องมีเสียงที่กำหนดเอง (รวมเสียงตัวอย่างที่ผู้ใช้มีสิทธิ์ใช้) และเครื่องมือปรับเสียง
3. **ขาดการควบคุมข้อความที่อ่าน** ผู้ใช้ต้องการระบุคำที่ไม่อ่าน เปลี่ยนคำหนึ่งเป็นอีกคำ แสดงสัญลักษณ์แทนคำที่กรอง หรือเว้นความเงียบก่อนอ่านต่อได้
4. **การนำไปใช้จริงกว้างกว่านิยาย** ต้องอ่านข้อความจาก Discord, YouTube Live Chat/Comments และแอปพลิเคชันอื่นผ่าน API ได้
5. **เสียงกับ Subtitle ต้องตรงกัน** เมื่อระบบอ่านแชทในไลฟ์ ข้อความ Subtitle ที่ปลายทาง (เช่น OBS) ต้องเริ่ม/เปลี่ยน/จบตาม **เสียงที่เล่นจริง** ไม่ใช่เวลาที่แชทเข้ามา
6. **ไม่อยากผูกกับการติดตั้งหรือไดรฟ์** เป้าหมายคือ Windows Portable ที่แตก ZIP แล้วใช้ได้ ย้ายโฟลเดอร์ไปเครื่องอื่นได้ และไม่บังคับให้ติดตั้ง Python รวมทั้งต้องคุมที่อยู่ไฟล์โมเดลและแคช

ด้วยเหตุนี้จึงเลือกทำเป็น **แพลตฟอร์ม TTS ที่แยกส่วน** แทนแอปอ่านนิยายเฉพาะทาง เพื่อให้สามารถเปลี่ยนโมเดลเสียงและ Input/Output Adapter ได้โดยไม่ทำลายระบบคำอ่าน การตั้งค่า หรือ API ที่ใช้อยู่

## 2. วัตถุประสงค์ (What success looks like)

- **ถูกต้อง:** ภาษาไทยเป็นลำดับแรก ผู้ใช้กำหนดคำอ่านหรือแก้จุดที่ผิดได้ และเสียงที่ออกจริงผ่านการทดสอบเป็นตัวตัดสิน
- **เสียงปรับแต่งได้:** เลือก Voice Profile, Speed, Pitch, Formant/EQ, การเว้นจังหวะ และความแสดงอารมณ์เท่าที่ Engine รองรับ; ทดลอง A/B เพื่อเปรียบเทียบ
- **พูดกับแสดงแยกกัน:** เก็บ Original Text, Spoken Text และ Display Text เป็นคนละข้อมูลพร้อมตำแหน่งอ้างอิง มีการ Mask/Replace/Skip/Silence ที่จัดการโดยกฎ
- **ใช้ซ้ำได้:** API เป็นแกนกลาง มีโหมดข้อความเป็นชุดและข้อความสด พร้อมคิว การยกเลิก การแจ้งสถานะ และการเชื่อมต่อกลับ
- **Subtitle ซิงก์เสียงจริง:** ข้อมูลเหตุการณ์ speech.started/segment/completed/cancelled ส่งให้หลาย Consumer; รองรับเว็บ Overlay สำหรับ OBS
- **พกพาและเป็นส่วนตัว:** ข้อมูลเสียงอ้างอิง, คีย์เชื่อมต่อ, โมเดล, กฎของผู้ใช้ เก็บในโฟลเดอร์ผู้ใช้ภายใน Portable หรือที่ผู้ใช้เลือกและไม่ขึ้น GitHub
- **สถาปัตยกรรมตรวจสอบได้:** โค้ดเป็นโมดูล ปรับ Engine ได้ ทดสอบอัตโนมัติ มี README, API Contract, Roadmap และแผนส่งต่อ

## 3. กลุ่มการใช้งาน (Primary use cases)

### A. ฟังนิยาย / บทความยาว
ผู้ใช้เปิดไฟล์ .txt หรือ .md เลือกโปรไฟล์เสียง และพจนานุกรมเฉพาะเรื่อง ระบบแบ่งประโยคและบท สร้างเสียงเป็นช่วง มี Cache และอ่านต่อจากจุดเดิมได้ในอนาคต หากพบออกเสียงผิด สามารถแก้คำอ่านแล้วสร้างใหม่ **เฉพาะช่วง** โดยไม่ต้องทำทั้งเล่ม

### B. ทดลองและจูนเสียงของตนเอง
เพิ่มไฟล์เสียงตัวอย่างที่เจ้าของเสียงอนุญาต เลือก Engine และตั้งค่าจูนเสียง ฟังประโยคชุดทดสอบที่มีสระ วรรณยุกต์ ชื่อเฉพาะ และคำอ่านยาก ระบบบันทึก Preset และเปรียบเทียบ A/B โดยระบุว่าการปรับค่าบางอย่างเป็น Native Engine Control หรือ DSP หลังสร้างเสียง

### C. อ่าน Live Chat บนสตรีม
รับข้อความจากแชทที่อนุญาต (Discord หรือ YouTube) คัดกรองข้อความ/ผู้ส่ง/ความยาว/Spam จัดคิว อ่านออกเสียงตามลำดับหรือความสำคัญ และส่ง Subtitle Event ให้ OBS Browser Source หรือโปรแกรมอื่นโดยไม่ผูกโค้ด TTS กับ OBS

### D. ระบบภายนอก เช่น เกมหรือ AI
โปรแกรมภายนอกเรียก HTTP API เพื่อส่งข้อความ, ระบุโปรไฟล์เสียงและนโยบายคำอ่าน แล้วสมัครรับเหตุการณ์ผ่าน WebSocket ในอนาคต เพื่อแสดง Subtitle บนจอหรือทำ Lip Sync โดยใช้ ID/ตำแหน่งเวลาเดียวกัน

## 4. หลักการสำคัญที่เลือก (Key decisions and reasons)

| การตัดสินใจ | เหตุผล | ผลต่อการพัฒนา |
|---|---|---|
| Thai-first | จุดเริ่มต้นคือการออกเสียงคำและวรรณยุกต์ภาษาไทย | มีชุดทดสอบคำไทยและตรวจฟังจริงก่อนขยายภาษา |
| Original / Spoken / Display แยกกัน | แก้คำอ่านได้โดยไม่ทำให้ Subtitle เปลี่ยนคำสะกด | ต้องมี Span Mapping และ Speech Plan |
| แปลงข้อความก่อนสร้างเสียง | ลดการเผลออ่านคำต้องห้ามหรือสัญลักษณ์ *** | กฎต้องทำงานก่อน TTS/Events; เสียงเงียบเป็น Segment จริง |
| Pluggable Voice Engines | คุณภาพและสิทธิ์ใช้โมเดลแตกต่างกัน | ทำ Engine Adapter, Capability Discovery และ License Audit |
| Playback clock เป็นตัวหลัก | เวลา Generated/Queued ไม่เท่ากับเวลาเสียงดัง | Coordinator เป็นผู้ประกาศ Event และ Segment จริง |
| Local-first API | ลดการพึ่ง Cloud และความเสี่ยงข้อมูลส่วนตัว | bind 127.0.0.1 เป็นค่าเริ่มต้น; คุมสิทธิ์เมื่อเปิด Remote |
| Portable ตั้งแต่ต้น | ต้องย้ายเครื่อง/ไดรฟ์ได้โดยไม่เสียการตั้งค่า | พาธสัมพันธ์กับ Root; ทดสอบบนเครื่องสะอาด; แยกข้อมูลกับโปรแกรม |
| โครงสร้างเป็นโมดูล | เพิ่ม Connector/Subtitle/Voice Profile ได้ในภายหลัง | มี Contract/Tests แยกแต่ละโมดูล |

## 5. ขอบเขตและสิ่งที่ยังไม่ตั้งเป็นข้อเท็จจริง

- ไม่สร้างโมเดลภาษาไทยใหม่จากศูนย์ตั้งแต่ต้น; เริ่มด้วยการประเมินตัวเลือก Engine ที่มีอยู่โดยดูคุณภาพ ความเร็ว เครื่องที่ใช้ และเงื่อนไขสิทธิ์
- Zero-shot Voice Cloning, Fine-tuning, Pitch/Formant/Emotion และ Streaming ต้องตรวจสอบความสามารถของโมเดลจริง บางค่าจำเป็นต้องใช้ DSP แทน
- เสียง “เป็นธรรมชาติ” และวรรณยุกต์ “ถูกต้อง” เป็นเกณฑ์ทดสอบเชิงคุณภาพ ไม่มีการรับประกันจากการมี Dictionary อย่างเดียว
- ลิขสิทธิ์ของ **โค้ดโปรเจกต์** ใช้ MIT; โมเดล น้ำหนักโมเดล เสียงตัวอย่าง และข้อมูลจากแพลตฟอร์มอยู่ภายใต้ข้อกำหนดเฉพาะของตน
- การแสดง Subtitle ระดับคำแบบ Karaoke ต้องมี Alignment ที่วัดจริง ห้ามประมาณตำแหน่งคำแบบสุ่ม
- Windows Portable แบบไม่ติดตั้ง Runtime เป็น **เป้าหมายการแจกจ่าย** ไม่ใช่ความสามารถของ Foundation ปัจจุบัน

## 6. สถานะ ณ วันที่จัดทำเอกสาร

Foundation v0.1.0 มี: โครง repo, MIT, การแทนคำด้วย Literal Rules, คำอ่านแบบ Dictionary Hint, การสร้างแผน Segment ประเภท speech/silence/skip, HTTP API แบบ loopback, หน้า HTML ทดลอง และ unit tests

ยังไม่มี: **โมเดลเสียงจริง, ไฟล์เสียงออก, Voice Cloning, Voice Studio เต็มรูปแบบ, Event WebSocket, YouTube/Discord Connector, Overlay ที่ซิงก์เสียง, Portable EXE** — ดูขั้นตอนใน [DEVELOPMENT_PLAN_TH.md](DEVELOPMENT_PLAN_TH.md)

## 7. ความสำเร็จสุดท้ายที่ผู้ใช้ควรสัมผัสได้

1. แตกไฟล์ ZIP Portable ที่ดาวน์โหลด/เตรียมโมเดลไว้แล้ว เปิดโปรแกรมได้โดยไม่ติดตั้ง Python
2. ใส่ข้อความ “ผู้ฝึกตนผู้นี้บรรลุความเป็นอมตะ” แล้วสั่งให้อ่านได้จริง ด้วยเสียงที่ตนเลือกและปรับแต่ง
3. ตั้งคำอ่าน “อมตะ” ให้ถูก แก้เฉพาะช่วงที่ผิด และเก็บค่าไว้ใช้ต่อ
4. ตั้งให้กรองคำหนึ่งเป็น "***" พร้อมช่วงเงียบ 400 ms หรือแทนด้วยคำสุภาพ โดย Subtitle แสดงตามที่กำหนด
5. ต่อ YouTube/Discord ได้เมื่ออนุญาตสิทธิ์ รับข้อความสดเข้าสู่คิวและอ่านข้อความ
6. ขณะเสียงดัง Subtitle แสดงตรงช่วงนั้นบน OBS และหายไปเมื่ออ่านจบ/ยกเลิก พร้อม Event ID ตรงกัน
7. API และข้อมูลตั้งค่ายังใช้ได้หลังย้ายโฟลเดอร์โปรแกรมไปยังไดรฟ์อื่น
