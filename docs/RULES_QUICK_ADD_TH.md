# เพิ่มกฎอ่านและกรองคำแบบละเอียดจากแบบฟอร์ม (Rules Quick Add)

หน้ากฎ **Rules — กฎการอ่านและกรองคำ (JSON Array)** มีส่วน **เพิ่มกฎอย่างรวดเร็ว** ที่สร้างกฎครบตามรูปแบบที่ Backend รองรับ โดยไม่ต้องเขียนหรือ Escape JSON เอง สามารถเพิ่มกฎเข้า JSON ที่กำลังแก้ไข แล้วกด **บันทึกในโปรแกรม** แยกต่างหาก การเพิ่มกฎในแบบฟอร์มยังไม่เปลี่ยนค่าที่บันทึกบนดิสก์จนกว่าจะกดบันทึก

## ตัวเลือกที่รองรับ

| ช่อง | ค่าที่รองรับ | ความหมาย |
| --- | --- | --- |
| รูปแบบการค้นหา (`match_mode`) | `literal` หรือ `five_run` | ข้อความตรงตัว หรือกลุ่มเลข 5 ติดต่อกันตั้งแต่ 3 ตัว (สำหรับเสียงหัวเราะ) |
| ข้อความที่ค้นหา (`match`) | ข้อความไม่ว่าง ไม่เกิน 200 ตัวอักษร | เมื่อเลือก `five_run` จะตั้งค่าเป็น `555` อัตโนมัติ |
| การทำงาน (`mode`) | `replace`, `skip`, `silence` | อ่านข้อความแทน / ข้ามคำ / แทรกช่วงเงียบ |
| คำอ่านแทน (`spoken`) | ข้อความไม่เกิน 500 ตัวอักษร | ใช้เฉพาะ `replace`; เว้นว่างให้อ่านข้อความเดิม |
| Subtitle (`display`) | ข้อความไม่เกิน 500 ตัวอักษร | ถ้าไม่กำหนด: `replace` แสดงข้อความที่พบ, `skip/silence` แสดง `***` |
| เวลาหยุด (`silence_ms`) | จำนวนเต็ม 0–10000 มิลลิวินาที | ใช้เฉพาะ `silence`; ค่าเริ่มต้น 400 มิลลิวินาที |
| แหล่งข้อความ (`sources`) | เลือกได้สูงสุด 32 ค่า ค่าแต่ละตัวไม่เกิน 64 ตัวอักษร | ไม่เลือก = ใช้ทุกแหล่งข้อความ; เลือก = ใช้เฉพาะรหัส source ที่ตรง |

รูปแบบ `literal` **ไวต่อตัวพิมพ์เล็ก/ใหญ่** และจับคำที่เป็นส่วนหนึ่งของข้อความอื่นได้ด้วย ปัจจุบันระบบ **ไม่รองรับ** กฎ Regex ที่ผู้ใช้กำหนดเอง ตัวเลือกจับคู่แบบไม่สนตัวพิมพ์ใหญ่เล็ก หรือการจับเฉพาะคำเต็ม; จึงไม่แสดงตัวเลือกที่ Backend ไม่รองรับ

## ตัวเลือกแหล่งข้อความที่มีให้เลือก

| ใน UI | Source ID ที่บันทึกลง JSON |
| --- | --- |
| ข้อความทั่วไป / API | `manual` |
| เอกสาร | `document` |
| YouTube LIVE (API) | `youtube-live` |
| YouTube LIVE (Browser) | `youtube-live-browser` |
| TikTok LIVE (TikFinity) | `tiktok-live` |
| TikTok LIVE (Extension) | `tiktok-live-extension` |
| Discord (Bot / Client) | `discord` |

ทั้ง Discord Bot และ Discord Client ใช้ source `discord` ร่วมกันตามระบบปัจจุบัน จึงแยกการกรองกฎตามสองโหมด Discord ไม่ได้ด้วยช่อง `sources` นี้

หากมีโปรแกรมอื่นส่งงานผ่าน API พร้อม Source ID ของตนเอง สามารถใส่ชื่อ Source ID เพิ่มเติมในช่อง **ชื่อแหล่งอื่น ๆ** โดยคั่นด้วยจุลภาค กฎจะทำงานเมื่อ Source ที่ส่งมาตรงกันเท่านั้น

## วิธีใช้

1. เปิดแท็บ **กฎการอ่านส่วนกลาง** และขยาย **เพิ่มกฎอย่างรวดเร็ว**
2. เลือกรูปแบบค้นหาและการทำงาน กรอกค่าที่เกี่ยวข้องกับโหมดนั้น
3. เลือกแหล่งข้อความเฉพาะช่องทางที่ต้องการ หรือไม่เลือกเพื่อให้ใช้ทุกช่องทาง
4. ตรวจ **ตัวอย่างกฎที่จะเพิ่ม (JSON)** แล้วกด **เพิ่มกฎลง JSON**
5. ทดสอบด้วย **ข้อความทดสอบกฎและคำอ่าน** โดยเลือก **แหล่งข้อความสำหรับทดสอบกฎ** ให้ตรงกับกฎที่สร้าง
6. เมื่อถูกต้องแล้วกด **บันทึกในโปรแกรม** ที่แถบ Rules เพื่อบันทึก `data/filters/rules.json`

หมายเหตุ: ปุ่ม **ตรวจ JSON** ตรวจโครงสร้าง JSON เบื้องต้น; Backend จะตรวจเงื่อนไขของแต่ละกฎเมื่อบันทึกหรือทดสอบ การบันทึกใช้ Revision ที่โหลดจากโปรแกรมเพื่อป้องกันทับการแก้ไขพร้อมกันหลายแท็บ

## ตัวอย่าง

**แทนคำอ่านเฉพาะ YouTube LIVE API:**

```json
{
  "match": "GGWP",
  "mode": "replace",
  "spoken": "เล่นได้ดีมาก",
  "sources": ["youtube-live"]
}
```

**ข้ามคำไม่สุภาพแต่ไม่อ่านออกเสียง:**

```json
{
  "match": "คำไม่สุภาพ",
  "mode": "skip",
  "display": "[ข้อความถูกกรอง]"
}
```

**หยุดเสียง 750 มิลลิวินาทีเฉพาะ TikTok Extension:**

```json
{
  "match": "คำต้องห้าม",
  "mode": "silence",
  "display": "[เงียบ]",
  "silence_ms": 750,
  "sources": ["tiktok-live-extension"]
}
```

**อ่าน `555` ต่อเนื่องเป็นเสียงหัวเราะ:**

```json
{
  "match": "555",
  "match_mode": "five_run",
  "mode": "replace",
  "spoken": "ฮ่า ฮ่า ฮ่า"
}
```

ลำดับกฎใน JSON มีผลเมื่อกฎหลายรายการตรงจุดเดียวกัน: ระบบเลือกตำแหน่งที่พบเร็วที่สุดก่อน จากนั้นเลือกข้อความที่ตรงยาวที่สุด และใช้ลำดับใน JSON ตัดสินเมื่อยังเสมอกัน

ข้อมูลในตัวอย่างนี้เป็นกฎรูปแบบที่ระบบรองรับจริง ไม่มีการเพิ่มวิธีจับคำใหม่หรือเปลี่ยนความหมายของ JSON เก่าครับ
