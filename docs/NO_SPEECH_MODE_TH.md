# โหมด "ไม่สร้างเสียง" และการรีเซ็ตคิว — VoxWeaveTTS

## ไม่สร้างเสียง

ในแท็บ **ตั้งค่า** มีส่วน **การประมวลผลข้อความ (ไม่สร้างเสียง)** สำหรับโหมดรับข้อความแต่ละรายการ:

- YouTube LIVE (API / Browser)
- TikTok LIVE (TikFinity / Extension)
- Discord / Discord Client
- VoxWeaveSTT (API)

**ค่าเริ่มต้น:** ไม่เปิดใช้กับโหมดใดเลย การตั้งค่าเป็นของ Core ในไฟล์ `data/settings/ai-processing.json` และเปลี่ยนได้โดยกด **บันทึก AI Settings** ตามระบบ Revision เดิม; ไม่ได้เก็บแค่ใน Browser หรือถูกลบทิ้งเมื่อ Refresh

**เมื่อตั้ง "ไม่สร้างเสียง" สำหรับโหมดใด:** ระบบยังรับข้อมูล ทำกฎข้อความเฉพาะโหมด กฎก่อน AI และหลัง AI รวมถึงการแปลหรือ Custom Prompt ตามการตั้งค่ากลางตามลำดับเดิม แต่ **ไม่เลือกโมเดล TTS ไม่สร้าง WAV ไม่ทำ Audio Render และไม่เล่นเสียง**

- **เปิด AI Processing + เลือกแปลภาษา:** ผลลัพธ์ในรายการและประวัติคือข้อความ **หลัง AI และกฎหลัง AI** ไม่ใช้ข้อความต้นฉบับมาทำเป็นคำแปลปลอม
- **ปิด AI Processing หรือเลือก "ไม่แปล / ไม่เรียก AI":** ผลลัพธ์เป็นข้อความหลังใช้กฎกรอง/แทนคำ โดยไม่เรียก AI
- **ข้อความถูกกรองให้ข้ามทั้งข้อความ:** แสดงสถานะข้าม ไม่แอบแสดงข้อความที่ถูกกรอง
- **ข้อความไม่มีเสียง:** ประมวลผลเสร็จในสถานะ `displayed` / **แสดงข้อความแล้ว (ไม่สร้างเสียง)** ไม่หลอกว่าเป็นงานอ่านเสียงสำเร็จ
- คิวเข้าระบบและทำงานตามลำดับเดิม สามารถเปิดการรับ/ประมวลผลอัตโนมัติต่อไปโดยไม่มีไฟล์เสียง; หาก **อ่านอัตโนมัติ** ปิดอยู่ จะยังเห็นข้อความรับเข้า แต่ต้องเลือกประมวลผลเองเมื่อต้องการผลหลัง AI

**การแสดงผล:** เมื่อเลือก **ทำงานบนคอมพิวเตอร์ (Core)** ข้อความที่แปลสำเร็จและประวัติอยู่ใน Core Dashboard แบบ Same-Origin ที่แสดงผลหลัง Refresh ได้ ไม่เผยแพร่เนื้อหาแชทผ่าน API สถานะสาธารณะหรือ SSE; โหมด Browser เดิมแสดงในรายการและประวัติของแหล่งข้อความนั้น

**ข้อจำกัด:** ตัวเลือกใช้เฉพาะ 7 โหมด Live / STT; โหมดสร้างเสียง (Studio) และอ่านเอกสาร (Reader) ยังคงทำงานเหมือนเดิม หากเลือกแปลภาษาและโมเดลแปลไม่พร้อม ระบบจะใช้แนวทาง fallback/skip ที่ตั้งค่าไว้ การไม่สร้างเสียงไม่ใช่การรับประกันว่าผล AI จะแปลถูกต้อง

## รีเซ็ตคิวข้อความ (Core)

ในโหมด Computer ปุ่ม **รีเซ็ตคิวข้อความ** ของแหล่งข้อความจะล้างงานที่รออยู่ในแหล่งข้อความนั้นตามจริง ได้แก่:

1. ข้อความ Pending ใน SourceManager และบัฟเฟอร์ของ ComputerRuntime
2. งานที่เข้า SpeechCoordinator แล้วแต่กำลังรอแปล/เตรียม, รอสร้าง WAV, หรือรอเล่น WAV
3. คิว Replay ที่ยังไม่ได้เริ่มของแหล่งข้อความนั้น
4. ป้องกันข้อความที่กำลังเข้า HTTP API ขณะกดรีเซ็ตเล็ดลอดกลับมาใหม่

**ไม่หยุดเสียงที่กำลังเล่นอยู่ ไม่ตัดงานเดียวที่กำลังแปล/สร้างเสียงอยู่ถ้ายังไม่มีการเล่นเสียง และไม่ตัดการเชื่อมต่อกับแหล่งข้อความ** ผู้ใช้สามารถใช้ปุ่ม **หยุดรับข้อความ** เมื่อต้องการหยุด Source และงานของแหล่งข้อความนั้นจริง ๆ

ปุ่มรีเซ็ตจะกดได้แม้คิว Source Pending จะเป็นศูนย์ ถ้า Core ยังมีงานแปล/เตรียม/สร้างเสียง/เสียงรอเล่นของโหมดนั้น โดยหลังคำสั่งจะแจ้งจำนวนรวมที่ลบ และจำนวน Job ที่ยกเลิกได้

ทุกคำสั่งถูกตรวจ Same-Origin และ `X-VoxWeaveTTS-Intent`; Browser Refresh ไม่สร้าง Worker/การเชื่อมต่อ/เสียงใหม่

## การทดสอบ

- `tests/test_no_speech_mode.py` ตรวจตั้งค่า, HTTP API จริง, ผลประมวลผลเมื่อ AI เปิดและปิด, กฎข้าม, ไม่มี WAV/Render และข้อมูล Dashboard
- `tests/no_speech_browser_smoke.cjs` ตรวจ Browser Direct/Prefetch FIFO แบบไม่เรียกเสียง
- `tests/ai_settings_ui_smoke.cjs` ตรวจบันทึก/โหลดตัวเลือก 7 โหมด
- `tests/source_feed_smoke.cjs` ตรวจผลข้อความหลังแปลเข้าสู่ประวัติไม่สร้างเสียง
- `tests/test_core_source_browser_controls.py` ตรวจ Reset คิวแปล/สร้างเสียง/รอเล่นที่รับแล้ว งานกำลังเล่น, Replay, แยกโหมด และ Races
- `tests/computer_dashboard_ui_smoke.cjs` ตรวจปุ่มรีเซ็ตและสถานะแบบไม่มี Pending แต่ยังมี WAV-ready
