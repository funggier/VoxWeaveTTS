# การอ่านอีโมจิแบบกำหนดคำเอง — YouTube LIVE และ Discord

ระบบอ่านอีโมจิเป็น **การตั้งค่าเฉพาะช่องทาง** ที่อยู่ในหัวข้อ **กำหนดการอ่านข้อความและข้อมูลพิเศษ** ของ 4 โหมด:

- YouTube LIVE (API)
- YouTube LIVE (Browser)
- Discord
- Discord Client

ทั้งสี่โหมดมี Checkbox **อ่านอีโมจิด้วยคำที่กำหนดเอง** และช่อง **พจนานุกรมคำอ่านอีโมจิ** คนละชุด โดยเริ่มต้น **ปิด** เพื่อรักษาการทำงานเดิม ค่าอยู่ใน `data/settings/mode-voices.json` และย้ายเครื่องไปพร้อมโฟลเดอร์ Portable ได้ตามปกติ

## วิธีตั้งค่า

1. เปิดแท็บ YouTube LIVE หรือ Discord ที่ต้องการ
2. ขยาย **กำหนดการอ่านข้อความและข้อมูลพิเศษ**
3. เปิด **อ่านอีโมจิด้วยคำที่กำหนดเอง**
4. พิมพ์หนึ่งรายการต่อหนึ่งบรรทัดเป็น `อีโมจิ = คำอ่าน` เช่น:

```text
😂 = หัวเราะ
❤️ = หัวใจ
👍🏽 = เยี่ยมมาก
🇹🇭 = ประเทศไทย
👨‍👩‍👧‍👦 = ครอบครัว
:party_parrot: = นกเต้น
:face-blue-smiling: = ยิ้มสีฟ้า
```

5. กด **บันทึกการอ่านข้อความ** ภายในหัวข้อการอ่านข้อความของโหมดนั้น
6. ทดลองข้อความใหม่ เช่น `สวัสดี 😂❤️` จะส่งไปสร้างเสียงเป็น `สวัสดี หัวเราะ หัวใจ` หากทั้งสองอีโมจิถูกกำหนดไว้

**รองรับอีโมจิ Discord แบบกำหนดเอง** ในข้อความ `<:party_parrot:123456789012345678>` และแบบเคลื่อนไหว `<a:party_parrot:123456789012345678>` ด้วยคำอ่านจากคีย์ `:party_parrot:` โดยไม่ต้องใส่ ID ซึ่งอาจเปลี่ยนในแต่ละเซิร์ฟเวอร์ หากต้องการกำหนดเฉพาะอีโมจิ ID เดียว ใช้คีย์เต็มเช่น `<:party_parrot:123456789012345678>` ได้เช่นกัน

**รองรับ YouTube Browser Emoji แบบรูปภาพ:** ตัวอ่าน Chat-only ดึงค่า `alt` ของ `img` ภายในข้อความที่หน้าแชทแสดงมาเป็น Unicode/โทเค็น เช่น `😂` หรือ `:face-blue-smiling:` แล้วส่งต่อให้พจนานุกรมจับคู่ ส่วน YouTube API จะใช้ข้อความตามที่ API ส่งมา หากผู้ให้บริการไม่ส่งรหัสอีโมจินั้นในข้อความ ระบบไม่สามารถเดาค่าอีโมจิจากรูปภาพเองได้

## พฤติกรรมและข้อจำกัด

- เมื่อ **ปิด** ตัวเลือกอีโมจิ ระบบไม่แทนค่าใด ๆ
- เมื่อ **เปิด** ระบบจะแทนเฉพาะอีโมจิหรือรหัสที่ตั้งค่า **ตรงกันทุกตัวอักษร** ไม่เดาคำอ่านของอีโมจิที่ไม่มีในรายการ
- รองรับ Unicode ที่ประกอบหลายตัว เช่น สีผิว ธง และอีโมจิครอบครัว โดยจะจับคู่รายการที่ยาวที่สุดก่อน
- คำอ่านของอีโมจิที่อยู่ในชื่อผู้ส่งและข้อความแชทใช้พจนานุกรมเดียวกันในโหมดนั้น เมื่อเปิดอ่านชื่อผู้ส่ง
- กฎใช้ตอน **ประกอบข้อความส่งให้ TTS** เท่านั้น ข้อความต้นฉบับในประวัติและช่องข้อความจะไม่ถูกแก้ โดย Subtitle ที่ซิงก์กับเสียงอาจแสดงคำอ่านแทนอีโมจิเพื่อให้ตรงกับเสียงพูด
- อีโมจิที่เขียนไม่ตรงกัน เช่น `❤` และ `❤️` อาจต้องตั้งแยกกันหากมี Variation Selector ต่างกัน
- สูงสุด 64 รายการต่อโหมด อีโมจิ 48 Unicode codepoints ต่อคีย์ และคำอ่าน 60 ตัวอักษรต่อรายการ ไม่อนุญาตใช้คำทั่วไปหรือ `@` เป็นคีย์อีโมจิ
- ระบบแทนคำทั่วไป/กฎการอ่านส่วนกลางยังทำงานตามเดิม ดังนั้นถ้าเคยสร้างกฎส่วนกลางแทน `@` ก็ยังต้องปิดกฎนั้นแยกจากระบบอีโมจิ
- เฉพาะ 4 โหมดข้างต้น ไม่รวม TikTok และไม่เปิดระบบ Gift กลับมา

การตั้งค่ารุ่นเก่าที่ไม่มี `read_emojis` หรือ `emoji_dictionary` จะโหลดได้ตามปกติ โดยถือว่าอ่านอีโมจิ **ปิด** และพจนานุกรมว่าง
