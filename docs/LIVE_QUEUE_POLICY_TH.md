# คิวอ่านข้อความสด — อ่านตามลำดับ / สุ่มลดคิว / เลือกโหมดแชทเอง

**สถานะ:** เพิ่มในซอร์สหลัง Windows Portable v0.8.0 — ยังไม่ได้เผยแพร่ Portable เวอร์ชันใหม่

## ค่าเริ่มต้น: อ่านทุกข้อความที่รับไว้ตามลำดับ

- ระบบอ่านข้อความ Live ใช้ **FIFO (เข้าก่อนอ่านก่อน)** ของแต่ละโหมด เช่น YouTube LIVE (API), YouTube LIVE (Browser), Discord, Discord Client, TikTok LIVE (TikFinity) และ TikTok LIVE (Extension)
- ยกเลิกข้อจำกัดเดิม **12 รายการ** ในคิวเว็บ และ **40 รายการ** ในคิวรับข้อความฝั่ง Python ที่ทำให้ข้อความใหม่ถูกข้ามเพียงเพราะเสียงอ่านไม่ทัน
- การตั้งค่า **เก็บประวัติที่อ่านแล้ว** (0–100) มีผลเฉพาะข้อความที่แสดงในหน้ารายการ ไม่ใช่การลบข้อความที่ยังรออ่าน การแสดงรายการบนจอจำกัดเฉพาะบางส่วนเพื่อไม่ให้ DOM โตตามคิวทั้งหมด
- เมื่อ Browser ปฏิเสธ Auto-play จะพักงานแต่เก็บข้อความรออ่านไว้ เพื่อให้ผู้ใช้กด **อ่านอัตโนมัติต่อ** ได้
- การกด **สร้างเสียงทดลองด้วยตนเอง** ไม่ล้างคิว Live โดยอัตโนมัติอีกต่อไป หากเสียงปัจจุบันถูกขัดจังหวะเพื่อทดลอง จะย้ายข้อความนั้นกลับไปหน้าคิวและกลับมาอ่านใหม่หลังเสียงทดลองจบ
- การกรองข้อความตามกฎ, ข้อความต้องห้าม, ข้อผิดพลาดจากแหล่งข้อมูลที่ไม่ส่งข้อความถึงเรา, ข้อความที่ถูกลบที่ YouTube เอง หรือผู้ใช้กด **รีเซ็ตคิวข้อความ** / **หยุด** ยังคงทำให้บางข้อความไม่ได้อ่านได้ตามการออกแบบ ความสามารถ FIFO รับรองเฉพาะรายการที่ระบบได้รับและยอมรับเข้าคิวแล้ว
- เมื่อโหมดปกติไม่จำกัดจำนวนคิว ข้อความจากไลฟ์ที่เร็วมากอาจทำให้คิวและการใช้ RAM โตต่อเนื่อง ควรใช้โหมดสุ่มด้านล่างหากต้องการลดการสะสม

## ตัวเลือก: สุ่มลดคิวเมื่อสะสมมากเกินกำหนด

ในหน้ารับข้อความของแต่ละโหมด มีช่องติ๊ก **สุ่มลดคิวเมื่อสะสมมากเกินกำหนด** พร้อมตัวเลข:

| ตัวเลือก | ค่าเริ่มต้น | ความหมาย |
| --- | --- | --- |
| เปิดใช้งาน | **ปิด** | หากปิด จะไม่สุ่มลบและอ่านทุกข้อความที่รับไว้ตาม FIFO |
| เมื่อคิวรอเกิน | **20** | เมื่อมีข้อความที่ *ยังไม่ได้เริ่ม* รออ่านมากกว่า 20 (21 ข้อความขึ้นไป) ให้เริ่มสุ่ม |
| สุ่มเก็บไว้ | **5** | สุ่มเลือกข้อความในคิวรออ่านให้เหลือเพียง 5 ข้อความ |

เมื่อคิวที่กำลังรออ่านเพิ่มจาก 20 เป็น 21 ข้อความ โปรแกรมจะเลือกข้อความ 5 รายการจาก 21 รายการแบบสุ่มโดยไม่มีรายการซ้ำ แล้วลบอีก 16 รายการ **เฉพาะจากคิวรอ** จะแสดงสถานะรายการที่ถูกตัดว่า **สุ่มลบจากคิว** และนับยอดในสถานะคิว ส่วนรายการที่ถูกสุ่มเก็บไว้ **ยังอยู่ในลำดับเวลาเดิม** ไม่สุ่มลำดับการอ่าน

**ไม่กระทบข้อความที่เริ่มทำงานแล้ว**: งานเดียวที่กำลังแปล, สังเคราะห์เสียง, อ่านเสียงหรือพักไว้เพื่อกดอ่านต่อจะดำเนินต่อจนจบโดยไม่ถูกนำเข้าสุ่มลบ การเปิดตัวเลือกขณะมีคิวมากกว่าเกณฑ์จะสุ่มลดคิวที่ค้างอยู่ทันที และถ้าปิดกลับก็หยุดลดคิวอีกครั้ง

สามารถปรับเกณฑ์ได้ระหว่าง **2–100000** รายการ โดยจำนวนที่จะเก็บต้องเป็นจำนวนเต็ม **ตั้งแต่ 1 และน้อยกว่าเกณฑ์** ค่าไม่ถูกต้องจะไม่เปิดการสุ่มลดเพื่อป้องกันการลบผิดพลาด

- ตัวเลือกนี้ใช้เฉพาะโหมดที่เปิด **อ่านข้อความใหม่อัตโนมัติ**; ข้อความแบบเลือกอ่านเองไม่ได้เข้าคิวสุ่ม
- สามารถ **Export / Import โปรไฟล์ของแหล่งแชท** เพื่อบันทึกค่าเปิด/ปิด เกณฑ์ และจำนวนสุ่มเก็บไว้กับโปรไฟล์นั้น (คีย์ `random_queue_enabled`, `random_queue_threshold`, `random_queue_keep`)
- ไฟล์โปรไฟล์รุ่นเก่าที่ไม่มีคีย์ดังกล่าวยัง Import ได้ โดยตั้งค่า **ปิด / 20 / 5** เสมอ
- การสุ่มเกิดในคิวของหน้าเว็บเมื่อรับข้อความจาก Source Manager; หากหน้าเว็บหยุดทำงานหรือพักทั้งแท็บ Backend อาจสะสมข้อความจนหน้าเว็บกลับมารับและลดคิวในภายหลัง ไม่ใช่การควบคุมการเก็บข้อความฝั่งแพลตฟอร์มภายนอก

## YouTube LIVE (Browser): เลือก Top chat / Live chat ด้วยตนเอง

ซอร์สรุ่นใหม่ **ถอดการคลิก Dropdown Top chat → Live chat อัตโนมัติทั้งหมด** โปรแกรมจะอ่าน DOM ตามตัวเลือกที่ปรากฏในหน้าต่าง Chat-only ของ YouTube โดยไม่เปิดเมนูหรือเปลี่ยนโหมดให้คุณ

**Top chat** เป็นโหมดที่ YouTube อาจกรองบางข้อความออกตั้งแต่ต้นทาง ส่วน **Live chat** โดยทั่วไปแสดงข้อความได้ครบกว่าตามนโยบายของ YouTube แต่ทั้งสองโหมดไม่รับประกันว่า Chrome/Edge หรือ YouTube จะส่งข้อความใหม่ครบทุกกรณี ระบบไม่อ่านประวัติที่อยู่ในหน้า DOM ตอนเริ่มเชื่อมต่อเป็นครั้งแรก

## รีเซ็ตคิวแบบไม่หยุดข้อความปัจจุบัน

ปุ่ม **รีเซ็ตคิวข้อความ** ยังคงมีไว้ เมื่อต้องการล้างข้อความที่ยังรออ่านทั้งหมดและเริ่มอ่านข้อความใหม่ โดยคงงานหนึ่งข้อความที่กำลังแปล/สร้างเสียง/อ่านค้างอยู่และเสียงที่พักไว้ให้ทำต่อจนจบ โปรแกรมจะล้างคิวทั้งเว็บและ Source Manager ตามสิทธิ์ของโหมด แต่ไม่ตัดการเชื่อมต่อแหล่งข้อมูล
